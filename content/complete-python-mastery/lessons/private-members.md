## یه مشکل ظریف توی `TagCloud`

کلاس `TagCloud` که توی درس قبل ساختیم، یه سوراخ داره. مشکل اینه که کاربر کلاس می‌تونه مستقیم به `tags` (همون دیکشنری داخلی) دسترسی داشته باشه و ازش سوءاستفاده کنه:

```python
cloud = TagCloud()
cloud.add("Python")

print(cloud.tags["PYTHON"])
# KeyError: 'PYTHON'
```

چون همه‌چیز واقعاً به‌شکل کوچیک ذخیره می‌شه، دسترسی مستقیم به `tags` (بدون رعایت قرارداد کوچیک‌نویسی) باعث خطا می‌شه — دقیقاً همون چیزی که کلاس قرار بود پنهانش کنه.

## راه‌حل: خصوصی‌کردن ویژگی

برای اینکه یه ویژگی از **بیرون کلاس** غیرقابل‌دسترسی بشه، اسمش رو با **دو زیرخط** شروع می‌کنیم:

```python
class TagCloud:
    def __init__(self):
        self.__tags = {}

    def add(self, tag):
        tag = tag.lower()
        self.__tags[tag] = self.__tags.get(tag, 0) + 1
```

الان اگه از بیرون بخوای بهش دسترسی داشته باشی:

```python
cloud = TagCloud()
print(cloud.tags)
# AttributeError: 'TagCloud' object has no attribute 'tags'

print(cloud.__tags)
# AttributeError: 'TagCloud' object has no attribute '__tags'
```

هیچ‌کدوم کار نمی‌کنن — این ویژگی الان **خصوصی**ه (private).

## نکته: «خصوصی» توی پایتون واقعاً خصوصی نیست

برخلاف زبان‌هایی مثل جاوا یا C#، پایتون مفهوم واقعی «عضو خصوصی» رو نداره. وقتی یه ویژگی رو با `__` شروع می‌کنی، پایتون پشت‌صحنه اسمش رو تغییر می‌ده — جلوش اسم کلاس رو اضافه می‌کنه:

```python
print(cloud._TagCloud__tags)
# {}
```

یعنی از نظر فنی، هنوز می‌شه بهش دسترسی داشت — فقط یه‌کم سخت‌تر شده. این رفتار به این می‌گیم **name mangling**.

## پس چرا اصلاً این کار رو می‌کنیم؟

هدف از این قرارداد، **امنیت نیست** — یه علامت هشداره برای کسی که از کلاست استفاده می‌کنه: «این بخش پیاده‌سازی داخلیه، بهش دست نزن، ممکنه بدون هشدار قبلی عوض بشه.» با این کار، جزئیات پیاده‌سازی رو از رابط عمومی کلاس جدا نگه می‌داری.
