## وراثت، وقتی خوبه

تا اینجا دیدیم وراثت چقدر مفیده: از تکرار کد جلوگیری می‌کنه. مثلاً:

```python
class Animal:
    def eat(self):
        print("eat")


class Bird(Animal):
    def fly(self):
        print("fly")
```

`Bird` متد `eat` رو از `Animal` به ارث می‌بره — منطقیه، چون هر پرنده‌ای می‌تونه غذا بخوره.

## اما زیاده‌روی توی وراثت، مشکل‌سازه

حالا فرض کن یه کلاس `Chicken` هم بسازیم که از `Bird` ارث می‌بره:

```python
class Chicken(Bird):
    pass
```

مشکل اینجاست: `Chicken` الان متد `fly` رو هم به ارث برده — ولی مرغ که نمی‌تونه پرواز کنه! این یه نمونه از **سوءاستفاده از وراثت**ه: چون یه رابطه‌ی ظاهری («مرغ یه پرنده‌ست») توی دنیای واقعی درسته، باعث نمی‌شه توی کد هم منطقی باشه.

## زنجیره‌های طولانی: وراثت چندسطحی

یه نمونه‌ی رایج‌تر از این مشکل، توی مدل‌کردن کارمندها دیده می‌شه: «یه کارمند یه شخصه، یه شخص یه موجود زنده‌ست، یه موجود زنده یه چیزه...» و از همین‌جا زنجیره‌ای مثل این شکل می‌گیره:

```python
class Thing:
    pass


class LivingCreature(Thing):
    pass


class Person(LivingCreature):
    pass


class Employee(Person):
    pass
```

به این می‌گیم **وراثت چندسطحی** (multi-level inheritance). ممکنه فلسفی و «درست» به‌نظر برسه، ولی توی نرم‌افزار واقعی فقط پیچیدگی اضافه می‌کنه. متدهایی که به یه کلاس اضافه می‌کنی باید یه مسئله‌ی واقعی کسب‌وکار رو حل کنن — نه اینکه چون توی دنیای واقعی یه حیوون می‌تونه غذا بخوره، کلاس `Animal` هم حتماً باید متد `eat` داشته باشه.

## قاعده‌ی کلی

وراثت رو به یکی-دو سطح محدود کن. هرچی زنجیره‌ی وراثت طولانی‌تر بشه، فهمیدن اینکه هر کلاس دقیقاً چی رو به ارث برده و چرا، سخت‌تر می‌شه — و احتمال سوءاستفاده‌هایی مثل «مرغی که پرواز می‌کنه» بیشتر.
