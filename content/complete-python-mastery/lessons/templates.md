## چرا بدنه‌ی ایمیل رو مستقیم توی کد ننویسیم

توی درس قبل، بدنه‌ی ایمیل رو مستقیم به‌شکل یه رشته‌ی کوتاه توی کد نوشتیم. ولی توی یه برنامه‌ی واقعی، بدنه‌ی ایمیل معمولاً چندین خط HTML هست — نوشتنش مستقیم توی کد پایتون، هم خوندنش سخت می‌کنه هم به‌روزرسانیش رو. راه‌حل معمول: بدنه رو توی یه فایل جدا (یه **قالب**، template) نگه داریم.

## یه فایل قالب با یه پارامتر

فرض کن این فایل `template.html` رو داریم:

```html
<h1>Hi $name</h1>
<p>This is our test email.</p>
```

`$name` اینجا یه **پارامتر**ه — یه جای خالی که قراره بعداً با یه مقدار واقعی جایگزین بشه. توی برنامه‌های واقعی معمولاً برای هر سناریو (خوش‌آمدگویی، بازنشانی رمز، تأیید سفارش) یه قالب جدا داریم.

## پر کردن قالب با `string.Template`

پایتون یه کلاس آماده به اسم `Template` توی ماژول `string` داره که دقیقاً برای همین کاره:

```python
from pathlib import Path
from string import Template

template = Template(Path("template.html").read_text())
body = template.substitute({"name": "John"})

print(body)
# <h1>Hi John</h1>
# <p>This is our test email.</p>
```

- اول محتوای فایل رو با `read_text()` می‌خونیم و یه آبجکت `Template` باهاش می‌سازیم.
- متد `substitute` یه دیکشنری از پارامترها می‌گیره (کلید = اسم پارامتر توی قالب، بدون `$`) و رشته‌ی نهایی رو با مقادیر جایگزین‌شده برمی‌گردونه.

می‌شه به‌جای دیکشنری، مستقیم آرگومان کلیدی هم داد — دقیقاً همون نتیجه:

```python
body = template.substitute(name="John")
```

## وصل‌کردن به ایمیل

نتیجه‌ی `substitute` یه رشته‌ی معمولیه، پس دقیقاً مثل درس قبل بهش `attach` می‌کنیم — فقط این‌بار به‌جای `"plain"`، از نوع `"html"` استفاده می‌کنیم تا کلاینت ایمیل، تگ‌های HTML (مثل `<h1>` و `<strong>`) رو واقعاً رندر کنه:

```python
message.attach(MIMEText(body, "html"))
```

## جمع‌بندی

نگه‌داشتن بدنه‌ی ایمیل توی یه فایل HTML جدا، و پرکردنش با `string.Template`، کد رو تمیزتر نگه می‌داره و اجازه می‌ده از قالب‌های HTML واقعی (با استایل، تگ‌های `<strong>` و غیره) استفاده کنیم — به‌جای رشته‌های ساده‌ی داخل کد پایتون.
