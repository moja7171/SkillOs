## فناوری بک‌اند

> این ویدیو نسبتاً قدیمیه، پس ارزیابی محبوبیت و بلوغِ هر پلتفرم (مثلاً «.NET Core هنوز کامل نیست») رو با احتیاط بخون — از اون‌موقع خیلی چیزها عوض شده. ولی روش فکر و معیارهای مقایسه، همون‌طور که مدرس تأکید می‌کنه، همچنان معتبرن.

بیا کاندیداهامون برای فناوری بک‌اند و سرویس رو بررسی کنیم. منظور از بک‌اند، سمت سرورِ اپ‌های وب و وب API‌ـه — پس بحثمون درباره‌ی اپ‌های وب، وب API، کنسول و سرویس‌هاست؛ برای ساده‌گی، همه‌شون رو «بک‌اند» می‌نامیم.

یه نکته: قرار نیست یه پیشنهاد قطعی درباره‌ی اینکه چه پلتفرمی برای بک‌اندت استفاده کنی بدیم. این کار عاقلانه نیست، چون عوامل زیادی هست که بدون شناخت عمیق از نیازمندی‌ها نمی‌شه همچین تصمیمی گرفت. کاری که می‌کنیم اینه که رقبای اصلی رو معرفی کنیم و مزایا و معایب هر کدوم رو بررسی کنیم. این کار انتخاب پلتفرم رو خیلی راحت‌تر می‌کنه.

کاندیداهای اصلی برای اپلیکیشن‌های بک‌اند (به ترتیب الفبا): NET. Classic، NET. Core، Java، Node.js، PHP و Python.

### .NET Classic (یا فقط .NET)

توسط مایکروسافت توی سال ۲۰۰۱ به‌عنوان پاسخی به Java بنیان‌گذاری شد. یه پلتفرم عمومی، شیءگرا و static-typed‌ـه، با فریم‌ورک‌هایی برای اپلیکیشن‌های دسکتاپ (WinForms و بعداً WPF) و اپ‌های وب/API (ASP.NET). توسعه توی .NET با Visual Studio انجام می‌شه — به عقیده‌ی مدرس این دوره، یکی از بهترین ابزارهای توسعه‌ی دنیا.

NET. کراس‌پلتفرم نیست، پس فقط برای اپلیکیشن‌های مبتنی بر ویندوز مرتبطه. performance‌ش خوبه، ولی پلتفرم‌های سریع‌تری مثل Node.js هم هست. NET. یه پلتفرم خیلی بالغ با کامپوننت‌های third-party زیاد و کامیونیتی بزرگه، ولی نقشه‌راهش خیلی واضح نیست چون به نظر می‌رسه مایکروسافت داره توسعه‌دهنده‌های NET. رو به سمت .NET Core هدایت می‌کنه.

### .NET Core

می‌شه بهش گفت نسل بعدی .NET‌، و هدفش پرکردن شکاف‌های .NET‌ـه — به‌خصوص پشتیبانی از cross-platform و performance. .NET Core یه پلتفرم منعطف و سریعه، ولی هنوز کاملاً پخته نشده — چند تا کمبود واضح داره مثل پشتیبانی ناقص از webhook، OData و ORM. اپلیکیشن‌های .NET Core رو می‌شه با Visual Studio، VS Code و IDE‌های محبوب دیگه ساخت. کامیونیتیش هنوز بزرگ نیست، ولی خیلی فعاله و سریع رشد می‌کنه — توی آخرین نظرسنجی توسعه‌دهنده‌های Stack Overflow، بعد از Node.js دومین فریم‌ورک سمت سرور رتبه‌بندی شده.

### Java

مدت‌هاست وجود داره و به نظر می‌رسه قراره بمونه. توی سال ۱۹۹۵ توسط Sun Microsystems ساخته شد، الان مال Oracle‌ـه، و یکی از محبوب‌ترین پلتفرم‌های امروزیه. مثل .NET، یه زبان عمومی، شیءگرا و static-typed‌ـه. توی سمت کلاینت هم امتحانش کرد (اپلت‌های Java، بعداً JavaFX) که موفقیت چندانی نداشت، ولی اکوسیستم اندروید با اپ‌هایی که به‌صورت native با Java نوشته می‌شن، یه جهش بزرگ بهش داد.

سمت سرورِ Java، Java EE نام داره (اخیراً به Jakarta Enterprise Edition تغییر نام داده) و هر چیزی که از یه پلتفرم سمت سرور انتظار داری رو ارائه می‌ده — اپ وب، وب API، دسترسی به دیتابیس و بیشتر — همه توی یه محیط کراس‌پلتفرم. Java کامیونیتی بزرگی داره؛ گاهی خیلی خودانتقادگره، ولی همچنان پشتیبانی خوبی برای هر چیز مرتبط با Java ارائه می‌ده.

### Node.js

یکی از جوان‌ترین پلتفرم‌های این لیست، بعد از .NET Core. توسط Ryan Dahl توی سال ۲۰۰۹ بنیان‌گذاری شد و برای اپ‌های وبِ با concurrency بالا بهینه شده. سینتکسش بر پایه‌ی JavaScript‌ـه، که یعنی dynamically-typed‌ـه، و به خاطر سینتکس آشنا و performance عالیش خیلی سریع پذیرفته شد. احتمالاً یکی از سریع‌ترین فریم‌ورک‌های موجوده و توی رتبه‌ی اول با .NET Core رقابت می‌کنه. Node.js برای فرایندهای طولانی‌مدت هدف‌گذاری نشده — پس برای ساخت سرویس ازش استفاده نکن — ولی برای اپ‌های وبی که به عملیات I/O همزمان و کوتاه زیادی نیاز دارن، باید بالای لیستت باشه.

### PHP

توسط Rasmus Lerdorf توی سال ۱۹۹۴ بنیان‌گذاری شد — حتی از Java هم قدیمی‌تره. ولی برخلاف Java که شیءگرا و static-typed‌ـه، PHP یه‌جورایی شلوغ و بی‌نظمه. یادگیریش خیلی راحته، ولی این راحتی هزینه‌ای هم داره — گاهی به نظر می‌رسه عجولانه بیرون اومده و به‌اندازه‌ی کافی صیقل نخورده. با این حال، یکی از محبوب‌ترین زبان‌های موجوده و کامیونیتی پرجنب‌وجوشی داره. PHP تمرکز کمتری روی اپ‌های وب و API طولانی‌مدت داره — اگه دنبال یه کامپوننت طولانی‌مدت هستی، بهتره جای دیگه‌ای رو نگاه کنی.

### Python

توسط Guido van Rossum توی سال ۱۹۸۹ بنیان‌گذاری شد و خیلی سریع تبدیل به یکی از محبوب‌ترین زبان‌های اسکریپتی شد. Python خیلی سریع به‌عنوان زبانی که تقریباً هر کاری می‌تونه انجام بده شناخته شد — می‌تونی پیداش کنی توی اپلیکیشن‌هایی که با پلتفرم‌های دیگه نوشته شدن، توی سیستم‌های یادگیری ماشین، و البته به‌عنوان اپ وب یا وب API. یکی از قوی‌ترین نقاط فروش Python، منحنی یادگیریشه — یکی از آسون‌ترین زبان‌ها برای یادگیریه و خیلی هم مدارا داره. Python کامیونیتی بزرگی هم داره که به کمک‌کننده‌بودن اعضاش معروفه. می‌تونی Python رو برای تقریباً هر نوع اپلیکیشنی در نظر بگیری — اپ وب، وب API، کنسول یا سرویس.

### جمع‌بندی: جدول مقایسه‌ای

| پلتفرم | نوع Typing | کراس‌پلتفرم | مناسب برای |
|---|---|---|---|
| .NET Classic | Static | نه (فقط ویندوز) | اپ‌های ویندوزی، جایی که IDE قوی و کامیونیتی بزرگ اهمیت داره |
| .NET Core | Static | بله | اپ وب/API سریع و مدرن، با پذیرش چند کمبود موقت |
| Java | Static | بله | اپلیکیشن‌های enterprise با نیاز به بلوغ و پایداری بالا |
| Node.js | Dynamic | بله | اپ‌های وب با I/O همزمان زیاد؛ نه برای سرویس‌های طولانی‌مدت |
| PHP | Dynamic | بله | یادگیری سریع، اکوسیستم بزرگ؛ نه برای کامپوننت طولانی‌مدت |
| Python | Dynamic | بله | یادگیری آسون، همه‌کاره — از وب تا یادگیری ماشین |

از این جدول به‌عنوان مرجع استفاده کن، وقت انتخاب پلتفرم برای بک‌اند، سرویس یا کنسول.
