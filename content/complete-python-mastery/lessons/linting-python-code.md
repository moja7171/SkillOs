## Linting در عمل

فرض کن این کد نامعتبر را می‌نویسی:

```python
print "Hello, World!"
```

این نحو در پایتون ۲ معتبر بود ولی در پایتون ۳ نیست. با ذخیره‌ی فایل، لینتر زیر این خط یک زیرخط قرمز می‌کشد و با نگه‌داشتن ماوس رویش پیام خطا را نشان می‌دهد: «Missing parentheses in call to print».

یک نمونه‌ی دیگر: اگر یک عبارت ناقص بنویسی (مثل `2 +` بدون عدد دوم)، لینتر می‌گوید «invalid syntax» — دقیقاً همان خطایی که در محیط تعاملی هم دیدیم.

فایده‌ی لینتینگ این است که لازم نیست برنامه را اجرا کنی تا این مشکلات را ببینی؛ همان لحظه که کد را می‌نویسی، لینتر نشانشان می‌دهد.

## پنل Problems

با کلید میان‌بر Shift+Cmd/Ctrl+M پنل Problems باز می‌شود که همه‌ی خطاهای پروژه — حتی فایل‌های بسته — را یک‌جا نشان می‌دهد. برای پروژه‌ای با چند فایل، این خیلی به‌کار می‌آید.

## Command Palette

با Shift+Cmd/Ctrl+P می‌توانی Command Palette را باز کنی و هر دستوری را در VS Code اجرا کنی؛ از جمله دستورهای مربوط به لینتینگ (که همه با پیشوند «Python» می‌آیند چون از افزونه‌ی Python هستند).

## لینترهای مختلف

لینترهای محبوب پایتون: Pylint (پیش‌فرض افزونه‌ی Python)، Flake8 و mypy (نوع‌بررسی). تفاوت اصلی‌شان در نحوه‌ی گزارش خطا و وضوح پیام‌هاست.
