## نیازمندی‌های غیرکارکردی رو کی تعریف می‌کنه؟

یکی از بزرگ‌ترین مشکلات نیازمندی‌های غیرکارکردی اینه که مشخص نیست چه کسی باید تعریفشون کنه. معمولاً انتظار داریم مشتری همراه با تحلیل‌گر سیستم، نیازمندی‌های کارکردی رو تعریف کنه — چون بهتر از هر کسی می‌دونن سیستم چیکار باید بکنه. ولی نیازمندی‌های غیرکارکردی داستان دیگه‌ایه.

توی بیشتر موارد، مشتری اصلاً درباره‌ی نیازمندی‌های غیرکارکردی و پیامدهاشون هیچ ایده‌ای نداره. توی تجربه‌ی مدرس این دوره، وقتی از مشتری پرسیده می‌شه SLA سیستم چقدره (به فرض که اصلاً بدونه SLA یعنی چی)، معمولاً جوابش «همیشه» ـه. وقتی پرسیده می‌شه زمان پاسخ‌دهی API چقدر باید باشه، جواب یه چیزی حدود ۱۰ میلی‌ثانیه‌ست.

پس ما، معمارها، توی بحث نیازمندی‌های غیرکارکردی دو نقش داریم:

### نقش اول: تعیین مرزها

باید به مشتری توضیح بدیم که آپ‌تایم ۱۰۰٪ واقع‌بینانه نیست و احتمالاً واقعاً هم لازم نیست. باید براش توضیح بدیم که شبکه‌ی فعلیش اجازه نمی‌ده یه فراخوانی API در کمتر از ۱۰۰ میلی‌ثانیه تموم بشه.

### نقش دوم: صحبت با اعداد واقعی

بعد از اینکه مرزها رو مشخص کردیم، می‌تونیم درباره‌ی مقادیر ممکن حرف بزنیم — و این بحث باید با اعداد واقعی پشتیبانی بشه. مثلاً وقتی درباره‌ی کاربران همزمان حرف می‌زنی، سعی کن عدد واقعی رو محاسبه کنی، نه اینکه یه عدد از کلاه دربیاری. برای نیازمندی performance هم همین‌طور، سعی کن اهداف واقع‌بینانه تعیین کنی.

یادت باشه: اگه سیستم قراره توسط کاربر نهایی استفاده بشه، لازم نیست سر هر میلی‌ثانیه بجنگی — کاربرها اصلاً متوجهش نمی‌شن.
