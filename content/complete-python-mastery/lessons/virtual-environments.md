## مشکل: فقط یه نسخه از هر پکیج

فرض کن با `pip install requests` یه نسخه از پکیج `requests` رو نصب کردی. حالا یه پروژه‌ی دیگه داری که به یه نسخه‌ی **قدیمی‌تر** همون پکیج نیاز داره. مشکل اینجاست: با ساختار پیش‌فرض، فقط یه نسخه از هر پکیج می‌تونه روی سیستم نصب باشه — نمی‌شه هم‌زمان دو نسخه‌ی مختلف از `requests` داشت.

## راه‌حل: محیط مجازی (Virtual Environment)

**محیط مجازی** یه پوشه‌ی ایزوله‌ست که یه نسخه‌ی مخصوص از مفسر پایتون و پکیج‌های مخصوص همون پروژه رو نگه می‌داره — کاملاً جدا از بقیه‌ی سیستم و بقیه‌ی پروژه‌ها. هر پروژه، محیط مجازی خودش رو داره.

```bash
python3 -m venv env
```

این دستور یه پوشه‌ی جدید (طبق قرارداد، اسمش `env`) می‌سازه که داخلش یه نسخه‌ی مستقل از مفسر پایتون و پوشه‌ای برای نصب پکیج‌ها (`site-packages`) هست.

## فعال‌سازی و غیرفعال‌سازی

قبل از استفاده، باید محیط مجازی رو **فعال** کنیم:

```bash
source env/bin/activate    # Mac/Linux
env\Scripts\activate.bat   # Windows
```

بعد از فعال‌سازی، هر `pip install` که بزنی، فقط توی همین محیط مجازی نصب می‌شه — نه به‌شکل سراسری روی سیستم.

```bash
pip install requests
```

وقتی کارت تموم شد:

```bash
deactivate
```

## جمع‌بندی

محیط مجازی یعنی هر پروژه، نسخه‌ی مخصوص خودش از پایتون و پکیج‌ها رو داره، بدون تداخل با بقیه‌ی پروژه‌ها. دستورهای بالا رو لازم نیست حفظ کنی — توی درس بعدی یه ابزار ساده‌تر می‌بینیم که این کار رو خودکار می‌کنه.
