## بذار خطا رو زودتر ببینیم

فرض کن این کد اشتباه رو می‌نویسی:

```python
print "Hello, World!"
```

این توی پایتون ۲ درست بود، ولی توی پایتون ۳ نه. همین که فایل رو ذخیره می‌کنی، لینتر زیر این خط یه زیرخط قرمز می‌کشه؛ ماوس رو نگه‌دار روش، پیام خطا رو می‌بینی: «Missing parentheses in call to print».

یه مثال دیگه: یه عبارت نصفه بنویس (مثل `2 +` بدون عدد بعدیش) — لینتر می‌گه «invalid syntax»، همون خطایی که قبلاً توی محیط تعاملی هم دیدیم.

فایده‌ی لینتینگ اینه که لازم نیست برنامه رو اجرا کنی تا این چیزا رو ببینی؛ همون لحظه که تایپ می‌کنی، بهت می‌گه.

## پنل Problems

با Shift+Cmd/Ctrl+M پنل Problems باز می‌شه — همه‌ی خطاهای پروژه رو یک‌جا نشونت می‌ده، حتی فایل‌هایی که الان باز نیستن.

## Command Palette

با Shift+Cmd/Ctrl+P می‌تونی Command Palette رو باز کنی و هر دستوری توی VS Code اجرا کنی — دستورهای لینتینگ هم اونجان (با پیشوند «Python»، چون از افزونه‌ی Python میان).

## چندتا لینتر مختلف

معروف‌ترین لینترهای پایتون: Pylint (پیش‌فرض افزونه‌ی Python)، Flake8 و mypy. فرقشون بیشتر توی طرز گزارش خطا و وضوح پیام‌هاست.
