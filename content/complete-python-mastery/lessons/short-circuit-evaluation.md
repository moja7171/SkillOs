## پایتون تا آخر همه‌چیزو حساب نمی‌کنه

بریم سراغ همون مثال بخش قبل:

```python
high_income = True
good_credit = True
student = False

if (high_income or good_credit) and not student:
    print("Eligible")
```

یه نکته‌ی مهم درباره‌ی `and` و `or`: این عملگرها **اتصالی‌کوتاه** (short-circuit) هستن. یعنی به محض اینکه نتیجه‌ی نهایی مشخص بشه، پایتون ارزیابی بقیه‌ی عبارت رو متوقف می‌کنه — حتی اگه هنوز بهشون نرسیده باشه.

## با `and`: به محض یه `False`، تمومه

```python
high_income = False
good_credit = True

print(high_income and good_credit)
```

پایتون از چپ شروع می‌کنه. همین که به `high_income` می‌رسه و می‌بینه `False`ه، دیگه لازم نیست `good_credit` رو چک کنه — نتیجه‌ی `and` هر جفتی که یه طرفش `False` باشه، خودش `False`ه. پس ارزیابی همون‌جا متوقف می‌شه (حتی اگه `good_credit` رو اصلاً نگاه نکرده).

## با `or`: به محض یه `True`، تمومه

```python
high_income = False
good_credit = True

print(high_income or good_credit)
```

اینجا برعکسه. پایتون اول `high_income` رو می‌بینه که `False`ه، پس ادامه می‌ده و `good_credit` رو هم چک می‌کنه. چون اون `True`ه، ارزیابی همون‌جا متوقف می‌شه و نتیجه `True` می‌شه — بدون اینکه (اگه بیشتر از دو شرط بود) لازم باشه بقیه رو هم چک کنه.

## چرا مهمه؟

اسمش از مدار الکترونیک اومده — همون‌جوری که یه مدار اتصالی‌کوتاه مسیر رو زودتر از موعد قطع می‌کنه. توی برنامه‌نویسی واقعی، این رفتار می‌تونه بهت کمک کنه از اجرای یه محاسبه‌ی سنگین یا یه فراخوانی غیرضروری (مثلاً چک‌کردن یه دیتابیس) جلوگیری کنی — اگه بذاریش دومین شرط توی یه `and`، و شرط اول از قبل `False` باشه، اون فراخوانی اصلاً اجرا نمی‌شه.

**قانون:**
- `and` روی اولین `False` متوقف می‌شه.
- `or` روی اولین `True` متوقف می‌شه.
