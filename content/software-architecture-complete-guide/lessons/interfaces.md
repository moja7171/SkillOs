## رابط‌ها (Interfaces)

اگه با یه پلتفرم شیءگرا مثل Java یا .NET کار می‌کنی، احتمالاً با اینترفیس‌ها آشنایی. اگه نه، احتمالاً زبان موردعلاقه‌ت مفاهیم مشابهی داره — مثل کلاس‌های انتزاعی (abstract classes) توی Python. به‌هرحال، بیا همه رو با اینترفیس‌ها هم‌سطح کنیم.

اینترفیس، یه **قرارداد** ـه که امضای (signature) یه پیاده‌سازی رو اعلام می‌کنه. اینترفیس می‌گه یه تکه کد که قراره یه کار خاص انجام بده، متدش چه شکلی خواهد بود.

مثلاً یه کد که چند محاسبه‌ی ریاضیِ ساده انجام می‌ده رو در نظر بگیر — برای سادگی، فرض کن فقط چهار عملیات پایه رو پشتیبانی می‌کنه:

```csharp
public interface ICalculator
{
    double Add(double x, double y);
    double Subtract(double x, double y);
    double Multiply(double x, double y);
    double Divide(double x, double y);
}
```

همون‌طور که می‌بینی، اینترفیس متدها و امضاشون رو تعریف می‌کنه، ولی هیچ پیاده‌سازی‌ای شامل نمی‌شه.

### اینترفیس‌ها به چه دردی می‌خورن؟

جواب ساده‌ست: استفاده از اینترفیس اجازه می‌ده کدمون **اتصال سست (loosely coupled)** بشه — یعنی یه کلاس رو به کلاس دیگه گره نزنیم. بیا با یه مثال روشنش کنیم.

فرض کن یه کلاس `Calculator` داریم و یه کلاس اصلی که بهش ارجاع می‌ده و ازش استفاده می‌کنه. بدون استفاده از اینترفیس، کدمون این‌شکلیه:

```csharp
public class MainClass
{
    private Calculator calc = new Calculator();

    public double Compute(double x, double y)
    {
        return calc.Add(x, y);
    }
}
```

همون‌طور که می‌بینی، کلاس اصلی باید کلاس `Calculator` رو بشناسه — مستقیم توی کدش ظاهر می‌شه. حالا اگه بخوای کلاس `Calculator` رو با یه کلاس بهتر و پیشرفته‌تر جایگزین کنی چی؟ باید کدِ کلاس اصلی رو تغییر بدی و دوباره کامپایلش کنی. این یعنی کلاس‌ها به هم گره خوردن و اتصالشون محکمه (strongly coupled).

یه ضرب‌المثل توی دنیای معماری نرم‌افزار هست که می‌گه: **«new چسبه.»** یعنی هر جا کلیدواژه‌ی `new` رو ببینی — مثل کدی که بالاتر دیدیم — یعنی یه پیوند محکم و اتصال قوی بین اون دو کلاس هست. اتصال محکمِ کلاس‌ها، معمولاً ایده‌ی بدیه و کدت رو کمتر ماژولار و انعطاف‌پذیر می‌کنه.

### با اینترفیس چی تغییر می‌کنه؟

بیا ببینیم اگه از اینترفیس استفاده کنیم چی می‌شه:

```csharp
public class MainClass
{
    private ICalculator calc = CalculatorFactory.GetInstance();

    public double Compute(double x, double y)
    {
        return calc.Add(x, y);
    }
}
```

توی این حالت، کلاس اصلی کلاس `Calculator` رو نمی‌شناسه، بلکه با یه اینترفیس کار می‌کنه. اینترفیس تعریف می‌کنه ماشین‌حساب چه کاری می‌تونه بکنه، ولی هیچ اشاره‌ای به پیاده‌سازیِ مشخصش نمی‌کنه. ماشین‌حساب می‌تونه با همون کلاسی که قبلاً دیدیم پیاده‌سازی بشه، یا با یه کلاس کاملاً متفاوت. کلاس اصلی هیچ ایده‌ای درباره‌ش نداره — و این‌طوری کدمون واقعاً ماژولار می‌شه. می‌تونیم پیاده‌سازی رو عوض کنیم بدون اینکه بقیه‌ی کد ازش خبردار بشه. این قدرت واقعی اینترفیس‌هاست.

### حالا پیاده‌سازی از کجا میاد؟

خب، بالاخره یه پیاده‌سازی وجود داره — کد اجرا می‌شه و نتیجه تولید می‌کنه. همون‌طور که دیدی، پیاده‌سازی از متد `GetInstance` برمی‌گرده. این متد از یه الگو به اسم **تزریق وابستگی (dependency injection)** استفاده می‌کنه تا یه نمونه — یه پیاده‌سازی مشخص — رو به اینترفیس تزریق کنه. این موضوع، درسِ بعدیه.

تا اون‌موقع، یادت باشه: new چسبه. همیشه استفاده از اینترفیس رو به ارجاع مستقیم بین کلاس‌ها ترجیح بده — کدت خیلی ماژولارتر و راحت‌تر برای تغییر و نگهداری می‌شه.
