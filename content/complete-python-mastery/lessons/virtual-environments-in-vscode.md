## مشکل: ویرایشگر از محیط مجازی خبر نداره

فرض کن با `pipenv install requests` این پکیج رو داخل محیط مجازی پروژه نصب کردی. ولی اگه فایل رو از داخل VS Code (یا هر ویرایشگر دیگه) اجرا کنی، ممکنه با خطای `ModuleNotFoundError: No module named 'requests'` مواجه بشی — با اینکه دستور `pipenv shell` توی ترمینال درست کار می‌کرد!

## چرا این اتفاق می‌افته

ویرایشگر کد به‌طور پیش‌فرض از **مفسر پایتونِ سراسریِ** نصب‌شده روی سیستم استفاده می‌کنه، نه از مفسر مخصوصِ محیط مجازیِ پروژه. اون مفسر سراسری هیچ‌وقت از وجود محیط مجازی پروژه خبردار نمی‌شه — پس پکیج‌های نصب‌شده‌ی داخل محیط مجازی رو نمی‌بینه.

## راه‌حل: انتخاب مفسر درست

اول باید مسیر محیط مجازی پروژه رو پیدا کنیم:

```bash
pipenv --venv
```

بعد توی VS Code، از نوار وضعیت پایین صفحه (جایی که نسخه‌ی پایتون نمایش داده می‌شه)، روی نسخه کلیک می‌کنیم و از لیست مفسرهای موجود، همونی که به مسیر محیط مجازی اشاره می‌کنه رو انتخاب می‌کنیم. اگه این مسیر توی لیست نبود، می‌شه دستی هم توی تنظیمات VS Code اضافه‌ش کرد.

بعد از انتخاب مفسر درست و بازکردن دوباره‌ی ویرایشگر، هم اجرای برنامه و هم قابلیت‌هایی مثل تکمیل خودکار و بررسی خطا (IntelliSense) دیگه پکیج‌های داخل محیط مجازی رو درست می‌شناسن.

## نکته

اگه ابزارهایی مثل linter (که توی درس‌های قبل دیدیم) رو قبلاً سراسری نصب کرده بودی، ممکنه بعد از سوییچ به محیط مجازیِ ایزوله، دیگه در دسترس نباشن — چون این محیط جدید، مستقل از پکیج‌های سراسریه. در این صورت باید اون ابزارها رو هم داخل همون محیط مجازی دوباره نصب کنی.
