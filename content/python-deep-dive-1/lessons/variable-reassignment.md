## انتساب دوباره = شیء جدید، نه تغییر شیء قبلی

```python
my_var = 10
my_var = 15
```

خط دوم مقدار داخل شیء ۱۰ را **عوض نمی‌کند**. یک شیء int **جدید** با مقدار ۱۵ در آدرسی دیگر ساخته می‌شود و ارجاع `my_var` به آن می‌رود. شیء در آدرس قبلی دست‌نخورده می‌ماند (و اگر ارجاع دیگری نداشته باشد، آزاد می‌شود).

همین برای این خط هم صادق است:

```python
my_var = my_var + 5
```

اینکه `my_var` دو طرف تساوی هست، گولت نزند. پایتون اول سمت راست را ارزیابی می‌کند: `my_var` یک int با مقدار ۱۰ است، ۱۰ + ۵ = ۱۵، شیء جدیدی با مقدار ۱۵ می‌سازد، و بعد `my_var` را به آن اشاره می‌دهد. محتوای شیء قبلی هیچ تغییری نکرده — در واقع محتوای یک int **هیچ‌وقت** نمی‌تواند تغییر کند (درس بعد: mutability).

## در کد

```python
>>> a = 10
>>> hex(id(a))
'0x...af0'
>>> a = 15
>>> hex(id(a))
'0x...b90'     # شیء دیگر
>>> a = a + 1
>>> hex(id(a))
'0x...eb0'     # باز هم شیء دیگر
```

## چیزی که غافلگیرت می‌کند

```python
>>> a = 10
>>> b = 10
>>> id(a) == id(b)
True
```

`a` و `b` به **همان** شیء اشاره می‌کنند — با اینکه جداگانه نوشته‌ای. دو سؤال پیش می‌آید: *آیا این امن است؟* (درس بعد، mutability) و *چرا پایتون این کار را می‌کند؟* (چند درس بعد، interning).
