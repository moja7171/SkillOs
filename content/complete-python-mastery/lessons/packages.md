## سازمان‌دهی ماژول‌ها توی زیرپوشه‌ها

هرچی برنامه بزرگ‌تر بشه، احتمالاً می‌خوای فایل‌ها رو توی زیرپوشه‌ها دسته‌بندی کنی — وگرنه با صدها ماژول توی یه پوشه‌ی واحد مواجه می‌شی. بیایم `sales.py` رو به یه زیرپوشه‌ی جدید به اسم `ecommerce` منتقل کنیم:

```
project/
├── app.py
└── ecommerce/
    └── sales.py
```

اگه حالا `app.py` رو اجرا کنی، خطا می‌گیری — پایتون دیگه `sales` رو پیدا نمی‌کنه، چون طبق درس قبل فقط توی پوشه‌ی فعلی و پوشه‌های نصب پایتون می‌گرده، نه توی زیرپوشه‌ها.

## `__init__.py`: تبدیل یه پوشه به پکیج

برای اینکه پایتون `ecommerce` رو به‌عنوان یه واحد قابل‌import بشناسه، باید یه فایل خالی به اسم `__init__.py` داخلش بذاریم:

```
project/
├── app.py
└── ecommerce/
    ├── __init__.py
    └── sales.py
```

همین که این فایل وجود داشته باشه، پایتون `ecommerce` رو یه **پکیج** (package) حساب می‌کنه. یه پکیج یعنی یه ظرف برای یک یا چند ماژول؛ توی سیستم فایل، پکیج معادل یه پوشه‌ست و ماژول معادل یه فایل.

## import کردن از داخل یه پکیج

حالا می‌شه ماژول `sales` رو با پیشوند اسم پکیجش import کرد:

```python
import ecommerce.sales

ecommerce.sales.calculate_tax()
```

این کار می‌کنه، ولی هر بار نوشتن `ecommerce.sales.` قبل از هر تابع، خسته‌کننده‌ست. یه روش بهتر:

```python
from ecommerce.sales import calculate_tax

calculate_tax()
```

و اگه چند تا اسم از یه ماژول لازم داری ولی می‌خوای خواناتر بمونه، می‌شه خود ماژول رو import کرد:

```python
from ecommerce import sales

sales.calculate_tax()
sales.calculate_shipping()
```

## جمع‌بندی

پکیج فقط یه پوشه با یه `__init__.py` داخلشه. برای دسترسی به ماژول‌های داخل پکیج، مسیرش رو با نقطه می‌نویسیم (`ecommerce.sales`) — دقیقاً همون‌طوری که مسیر فایل‌ها رو با اسلش می‌نوشتیم، فقط برای import.
