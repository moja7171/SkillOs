## نه فقط مدیریت‌کردن — خودت هم می‌تونی استثنا صادر کنی

تا الان یاد گرفتیم چطور استثناهایی که پایتون صادر می‌کنه رو مدیریت کنیم. ولی می‌شه توی کد خودمون هم عمداً یه استثنا صادر کرد — با عبارت `raise`.

## یه مثال: اعتبارسنجی ورودی تابع

```python
def calculate_x_factor(age):
    if age <= 0:
        raise ValueError("Age cannot be 0 or less")
    return 10 / age
```

اگه `age` نامعتبر باشه (صفر یا منفی)، به‌جای اینکه بذاریم تابع با یه خطای گنگ (مثل `ZeroDivisionError`) کرش کنه، خودمون **عمداً** یه `ValueError` با یه پیام روشن صادر می‌کنیم.

## استفاده از تابع

```python
x_factor = calculate_x_factor(-1)
```

اگه این خط رو بدون محافظت اجرا کنی، برنامه کرش می‌کنه:
```
ValueError: Age cannot be 0 or less
```

طبق چیزی که قبلاً یاد گرفتیم، باید این احتمال رو مدیریت کنیم:

```python
try:
    x_factor = calculate_x_factor(-1)
except ValueError as error:
    print(error)
```

## از کجا نوع استثنا رو انتخاب کنیم؟

پایتون از قبل یه سری استثنای آماده داره (`ValueError`، `ZeroDivisionError`، `TypeError`، ...) که برای اکثر موقعیت‌ها کافی‌ان — توی مستندات رسمی پایتون، یه فهرست کامل از این استثناهای درونی هست، با یه سلسله‌مراتب (مثلاً `ZeroDivisionError` زیرمجموعه‌ی `ArithmeticError`ه). بعداً، وقتی کلاس‌ها رو یاد بگیری، می‌تونی نوع استثنای سفارشی خودت رو هم تعریف کنی — ولی این کار زیاد لازم نمی‌شه.

## یه نکته‌ی مهم برای درس بعدی

صادرکردن استثنا کار مفیدیه، ولی **رایگان نیست**. توی درس بعدی می‌بینیم که صادرکردن استثنا یه هزینه‌ی واقعی داره — و کِی بهتره به‌جاش از یه راه ساده‌تر (مثل یه `if` معمولی) استفاده کنیم.
