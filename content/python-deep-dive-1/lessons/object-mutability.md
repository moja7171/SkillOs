## تغییر «وضعیت داخلی» یک شیء

هر شیء یک نوع دارد، داده‌ای درونی (state) دارد، و در آدرسی از حافظه نشسته. تغییر دادن آن داده‌ی درونی یعنی **تغییر state**.

مثال: `my_account` به شیئی از نوع `BankAccount` در آدرس ۱۰۰۰ اشاره می‌کند با `account_number = 12345` و `balance = 150`. پولی واریز می‌کنیم و `balance` می‌شود ۵۰۰. **داده عوض شد ولی آدرس نه** — همان شیء است. می‌گوییم شیء **mutate** شد.

این با int فرق دارد: وقتی `my_var = 10` را به `my_var = 15` تغییر دادیم، ارجاع به شیء جدیدی رفت. اینجا خود شیء درجا عوض شد.

## دو تعریف

- **Mutable**: شیئی که state درونی‌اش می‌تواند تغییر کند.
- **Immutable**: شیئی که state درونی‌اش نمی‌تواند تغییر کند.

| Immutable | Mutable |
|---|---|
| همه‌ی اعداد: `int`, `float`, `bool`, `complex` | `list` |
| `str` | `set` |
| `tuple` | `dict` |
| `frozenset` | کلاس‌های خودت (اگر اجازه‌ی تغییر بدهند) |
| کلاس‌های خودت (اگر راهی برای تغییر ندهند) | |

## در کد: append در برابر +

```python
>>> my_list = [1, 2, 3]
>>> id(my_list)
140...2632
>>> my_list.append(4)
>>> my_list, id(my_list)
([1, 2, 3, 4], 140...2632)     # همان شیء؛ state تغییر کرد

>>> my_list_1 = [1, 2, 3]
>>> id(my_list_1)
140...4160
>>> my_list_1 = my_list_1 + [4]
>>> my_list_1, id(my_list_1)
([1, 2, 3, 4], 140...9088)     # شیء جدید!
```

`append` شیء را درجا تغییر می‌دهد. `+` دو لیست را به هم می‌چسباند و **لیست تازه‌ای برمی‌گرداند**؛ بعد ارجاع عوض می‌شود. نتیجه‌ی ظاهری یکی است، سازوکار نه.

دیکشنری هم همین‌طور: `my_dict['key3'] = 10.5` کلید اضافه می‌کند و `id(my_dict)` ثابت می‌ماند.

## نکته‌ی ظریف: tuple immutable با عناصر mutable

```python
t = (1, 2, 3)
```

tuple immutable است (نمی‌شود عنصر اضافه/حذف/جایگزین کرد) و عناصرش هم int هستند که immutable‌اند. این tuple واقعاً «یخ‌زده» است.

```python
a = [1, 2]
b = [3, 4]
t = (a, b)
a.append(3)
b.append(5)
t        # ([1, 2, 3], [3, 4, 5])
```

tuple همچنان immutable است: هیچ عنصری اضافه، حذف یا جایگزین نشد — دو ارجاع داخلش همان دو آدرس قبلی‌اند. ولی **اشیایی که به آن‌ها اشاره می‌کند** تغییر کردند، چون لیست‌اند. از دید ما «مقدار t عوض شد».

پس immutability یعنی «این *container* را نمی‌شود تغییر داد»، نه «هیچ‌چیز مربوط به آن هرگز عوض نمی‌شود». وقتی با collection کار می‌کنی، به این تفاوت دقت کن.

```python
>>> t = ([1, 2], [3, 4])
>>> t[0].append(3)      # مجاز
>>> t
([1, 2, 3], [3, 4])
>>> t[0] = [9]          # TypeError: 'tuple' object does not support item assignment
```
