## نام‌های مجاز

یک نام (identifier) در پایتون:

- با **حرف یا زیرخط** شروع می‌شود، بعدش حرف، رقم یا زیرخط.
- به بزرگی/کوچکی حروف حساس است: `count` و `Count` دو نام جدا هستند.
- نمی‌تواند یک **کلیدواژه** باشد: `if`, `def`, `class`, `None`, `True`, `lambda`, ... (لیست کامل در `keyword.kwlist`).

```python
>>> import keyword
>>> keyword.iskeyword("lambda"), keyword.iskeyword("print")
(True, False)
```

`print` کلیدواژه نیست، یک تابع built-in است — پس *می‌توانی* بنویسی `print = 5`، و بعد `print("x")` خطا می‌دهد. مجاز بودن یعنی کار می‌کند، نه اینکه ایده‌ی خوبی است.

## قراردادهای زیرخط

زیرخط در ابتدا و انتهای نام **معنا** دارد (بیشتر قرارداد، کمی هم رفتار واقعی):

| شکل | معنا |
|---|---|
| `_name` | «داخلی/خصوصی» — قرارداد است؛ `from module import *` آن را وارد نمی‌کند |
| `__name` | name mangling در کلاس: پایتون آن را به `_ClassName__name` تغییر می‌دهد تا در زیرکلاس‌ها تصادفاً بازنویسی نشود |
| `__name__` | «dunder» — نام‌های ویژه‌ی خود پایتون مثل `__init__`, `__len__`. **خودت dunder جدید نساز** |
| `_` | متغیر «دور بریز»: `for _ in range(3)` یا `first, _ = pair` |

## قراردادهای PEP 8

- **متغیرها و توابع**: `snake_case` — `total_price`, `read_rows`
- **کلاس‌ها**: `CamelCase` — `BankAccount`
- **ثابت‌ها**: `UPPER_SNAKE` — `MAX_RETRIES` (پایتون ثابت واقعی ندارد؛ این هم قرارداد است)
- **ماژول‌ها**: کوتاه و کوچک: `utils.py`
- نام‌های توصیفی بهتر از کوتاه‌های رمزی‌اند: `retry_count` نه `rc`.
