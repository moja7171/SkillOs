## یک دستور در چند خط

پایتون پایان یک دستور را با **پایان خط** می‌فهمد، نه با `;`. پس وقتی دستوری بلند می‌شود، باید به پایتون بگویی «هنوز تمام نشده». دو راه هست:

**۱. ادامه‌ی ضمنی (implicit)** — داخل `()`، `[]` و `{}` می‌توانی آزادانه خط بشکنی. این روش ترجیحی است:

```python
total = (first_value
         + second_value
         - discount)

names = [
    "Ali",
    "Sara",   # کامنت هم مجاز است
    "Reza",
]
```

**۲. ادامه‌ی صریح (explicit)** — با `\` در انتهای خط. کارآمد ولی شکننده: بعد از `\` هیچ‌چیز، حتی فاصله یا کامنت، نباید بیاید:

```python
if a > 0 \
   and b > 0 \
   and c > 0:
    print("all positive")
```

نکته‌ی سبکی: اگر یک عبارت آن‌قدر بلند است که به `\` نیاز دارد، معمولاً بهتر است دور آن پرانتز بگذاری.

## رشته‌های چندخطی

رشته با `'''` یا `"""` می‌تواند چند خط داشته باشد و **همه‌ی خطوط جدید و فاصله‌ها بخشی از رشته‌اند**:

```python
message = """Dear user,
    thanks for signing up.
Bye"""
print(repr(message))
# 'Dear user,\n    thanks for signing up.\nBye'
```

تورفتگی داخل رشته‌ی چندخطی هم داخل رشته می‌ماند — یک منبع رایج خطا وقتی رشته‌ی چندخطی را داخل تابع تورفته می‌نویسی. راه‌حل: `textwrap.dedent` یا کنار هم گذاشتن رشته‌های کوتاه داخل پرانتز:

```python
message = ("Dear user,\n"
           "thanks for signing up.\n"
           "Bye")
```

رشته‌ی سه‌کوتیشنی که به هیچ متغیری منتسب نشود، به‌عنوان **docstring** (اگر اول تابع/کلاس/ماژول باشد) یا صرفاً یک عبارت بی‌اثر عمل می‌کند — بعضی‌ها از آن به‌عنوان «کامنت چندخطی» استفاده می‌کنند، که فنی است ولی docstring واقعی نیست.
