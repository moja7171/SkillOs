## یه کلاس، چند والد

توی پایتون یه کلاس می‌تونه بیش از یه کلاس والد داشته باشه — به این می‌گیم **وراثت چندگانه** (multiple inheritance):

```python
class Employee:
    def greet(self):
        print("employee greet")


class Person:
    def greet(self):
        print("person greet")


class Manager(Employee, Person):
    pass
```

## مشکل: کدوم متد اجرا می‌شه؟

هر دو کلاس والد یه متد `greet` دارن. وقتی `Manager` هیچ‌کدوم رو خودش تعریف نکنه، کدوم اجرا می‌شه؟

```python
m = Manager()
m.greet()  # employee greet
```

پایتون اول به خود `Manager` نگاه می‌کنه، بعد **به ترتیبی که کلاس‌های والد نوشته شدن** می‌گرده. چون `Employee` قبل از `Person` نوشته شده، `Employee.greet` برنده می‌شه.

## چرا این خطرناکه

مشکل اینجاست: اگه یه نفر دیگه توی تیم بیاد و بدون اینکه بدونه، ترتیب والدها رو عوض کنه...

```python
class Manager(Person, Employee):
    pass
```

...حالا `m.greet()` یه پیام کاملاً متفاوت چاپ می‌کنه (`person greet`)! رفتار برنامه بی‌سروصدا عوض شده، فقط با جابه‌جایی ترتیب دو تا اسم.

## یه مثال خوب از وراثت چندگانه

وراثت چندگانه همیشه بد نیست — مشکل وقتیه که کلاس‌های والد چیز مشترکی دارن (مثل `greet` بالا). اگه کلاس‌های والد کوچیک، ساده و کاملاً بی‌ربط به هم باشن، ترکیب‌کردنشون کاملاً منطقیه:

```python
class Flyer:
    def fly(self):
        print("fly")


class Swimmer:
    def swim(self):
        print("swim")


class FlyingFish(Flyer, Swimmer):
    pass
```

اینجا هیچ تداخلی نیست — `FlyingFish` هم `fly` رو داره هم `swim` رو، و چون این دو تا هیچ متد مشترکی ندارن، ترتیب نوشتنشون هم اهمیتی نداره.

## جمع‌بندی

وراثت چندگانه، مثل وراثت چندسطحی، منبع بالقوه‌ی باگه — استفاده‌ش رو به مواقعی محدود کن که کلاس‌های والد کوچیک، مستقل و بدون همپوشانی‌ان.
