## پایتون از کجا می‌فهمد یک شیء دیگر لازم نیست؟

وقتی می‌نویسی `my_var = 10`، پایتون شیء int را در آدرسی (مثلاً ۱۰۰۰) می‌سازد و `my_var` به آن اشاره می‌کند. پایتون برای هر شیء حساب می‌کند **چند متغیر به آن اشاره دارند**: اینجا یکی، پس **reference count** آن شیء ۱ است.

```python
other_var = my_var
```

این خط مقدار ۱۰ را به `other_var` نمی‌دهد؛ **ارجاع** `my_var` (همان ۱۰۰۰) را به `other_var` می‌دهد. دو شیء با مقدار ۱۰ نداریم — یک شیء داریم با دو اشاره‌گر. شمارنده می‌شود ۲.

حالا اگر `my_var` از دامنه خارج شود یا به چیز دیگری (حتی `None`) اشاره کند، شمارنده به ۱ برمی‌گردد. اگر `other_var` هم برود، شمارنده **صفر** می‌شود و memory manager می‌گوید: «هیچ ارجاعی نمانده، این شیء را لازم ندارم» — شیء دور انداخته می‌شود و فضایش آزاد. این **reference counting** است و کاملاً خودکار انجام می‌شود.

## دیدن شمارنده: `sys.getrefcount`

```python
import sys

a = [1, 2, 3]
sys.getrefcount(a)     # 2  ← نه ۱!
```

چرا ۲؟ چون پاس دادن `a` به تابع، خودش یک ارجاع دیگر می‌سازد (آرگومان تابع به همان شیء اشاره می‌کند). پس `getrefcount` همیشه یکی بیشتر نشان می‌دهد — کافی است یکی کم کنی.

مدرس عمداً از **لیست** استفاده می‌کند نه عدد؛ با int نتیجه‌ای می‌گیری که غافلگیرت می‌کند (به‌خاطر interning — چند درس بعد).

## راه دقیق‌تر: `ctypes`

```python
import ctypes

def ref_count(address: int):
    return ctypes.c_long.from_address(address).value

ref_count(id(a))       # 1
```

اینجا **آدرس** (یک عدد) را پاس می‌دهیم نه خود متغیر را، پس شمارنده تغییر نمی‌کند. و اگر می‌پرسی «مگر `id(a)` خودش ارجاع نمی‌سازد؟» — چرا، ولی `id()` قبل از فراخوانی `ref_count` تمام می‌شود و ارجاعش را آزاد می‌کند؛ تا زمان اجرای `ref_count` شمارنده دوباره ۱ است.

```python
b = a;  ref_count(id(a))   # 2
c = a;  ref_count(id(a))   # 3
c = 10; ref_count(id(a))   # 2
b = None; ref_count(id(a)) # 1
```

## هشدار: آدرس، بعد از مرگ شیء

```python
a_id = id(a)
a = None
ref_count(a_id)   # 1؟ 0؟ یک عدد عجیب؟
```

وقتی آخرین ارجاع رفت، memory manager آن آدرس را برای استفاده‌ی مجدد آزاد می‌کند. بعد از آن، در آن آدرس **هر چیزی** ممکن است باشد — آشغال، یا شیئی دیگر. برای همین در پایتون هیچ‌وقت مستقیم با آدرس حافظه کار نمی‌کنیم؛ اینجا فقط برای فهمیدن سازوکار زیرین است.

درس بعد: **garbage collection** که به reference counting مربوط است ولی همان نیست.
