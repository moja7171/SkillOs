## اندازه‌گیری زمان اجرا با `timeit`

ماژول `timeit` بهت اجازه می‌ده زمان اجرای یه تیکه کد رو دقیق اندازه بگیری — با اجراش چندین بار پشت‌سرهم:

```python
from timeit import timeit

code = """
def calculate_x_factor(age):
    if age <= 0:
        raise ValueError("Age cannot be 0 or less")
    return 10 / age

try:
    x_factor = calculate_x_factor(-1)
except ValueError:
    pass
"""

duration = timeit(code, number=10_000)
print("raise version:", duration)
```

`timeit(کد, number=n)` همون کد رو `n` بار اجرا می‌کنه و مجموع زمانش رو برمی‌گردونه. اینجا `pass` رو توی `except` گذاشتیم چون نمی‌خوایم هزارها پیام چاپ بشه توی خروجی — `pass` یعنی «هیچ کاری نکن»، و برای بلوک‌های خالی لازمه، چون پایتون بلوک خالی رو قبول نمی‌کنه.

## نسخه‌ی بدون `raise`

حالا بیایم همین تابع رو **بدون** صادرکردن استثنا بنویسیم — به‌جاش `None` برگردونیم:

```python
code2 = """
def calculate_x_factor(age):
    if age <= 0:
        return None
    return 10 / age

x_factor = calculate_x_factor(-1)
if x_factor is None:
    pass
"""

duration2 = timeit(code2, number=10_000)
print("return-None version:", duration2)
```

## نتیجه

وقتی این دو تا رو مقایسه کنی، نسخه‌ی دوم (بدون `raise`) تقریباً **چهار برابر سریع‌تر** اجرا می‌شه. صادرکردن یه استثنا رایگان نیست — پایتون باید یه شیء استثنا بسازه و دنبال نزدیک‌ترین `except` متناظر بگرده، و این کار از یه مقایسه‌ی ساده‌ی `if` سنگین‌تره.

## یه نکته‌ی مهم

این تفاوت فقط وقتی محسوسه که این کد **هزاران بار** اجرا بشه. اگه یه تابع رو فقط چندبار صدا می‌زنی (مثلاً توی یه برنامه‌ی کوچیک برای چند نفر)، این تفاوت کارایی عملاً بی‌اهمیته.

## قاعده‌ی کلی

قبل از اینکه توی یه تابع `raise` بذاری، یه لحظه فکر کن: می‌شه همین موقعیت رو با یه `if` معمولی مدیریت کرد؟ اگه بشه، این راه هم تمیزتره هم (توی مقیاس بزرگ) سریع‌تر. فقط وقتی واقعاً لازمه که استثنا صادر کن — نه به‌عنوان روش پیش‌فرض کنترل جریان برنامه.
