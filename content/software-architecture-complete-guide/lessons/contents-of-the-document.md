## محتوای سند

یکی از داغ‌ترین بحث‌های جامعه‌ی معمارها، فرمتِ سند معماریه. یه سری استانداردِ گاهی‌استفاده‌شده هست که انواع مختلفِ نمودار و دیاگرام رو برای راحت‌تر فهمیدنِ معماری تعریف می‌کنن. یکی از معروف‌ترین‌هاشون UML‌ـه.

**UML** یه زبانِ مدل‌سازیه که کمک می‌کنه طراحیِ سیستم رو تجسم کنی. شامل مفاهیم نرم‌افزاری مثل فعالیت‌ها، اجزا و تعاملات، و همچنین دیاگرام‌هایی که طراحیِ سیستم رو تجسم می‌کنن — مثل دیاگرام کلاس و دیاگرام use case‌ـه.

با این حال، مدرس این دوره معمولاً از UML توی سندهای معماریش استفاده نمی‌کنه. دلیلش خیلی ساده‌ست: یادته مخاطبِ سند رو گفتیم؟ خوبه. بیشتر مخاطب‌ها با UML آشنا نیستن و اصلاً نمی‌فهمن دیاگرام‌ها و اصطلاحات مختلف چه معنی‌ای دارن. اگه سند پر از این‌جور چیزها باشه، خودت رو غرقِ توضیح‌دادنِ ساده‌ی اینکه منظورت چی بوده و واقعاً چی باید توسعه داده بشه می‌بینی.

### ساده باشه

بر اساس تجربه‌ی طراحیِ صدها سیستم، مؤثرترین سند معماری، ساده‌ترینشه. یعنی فقط از زبانِ ساده استفاده کن. با کلمات ساده توضیح بده طراحیِ سیستم چیه. توی کلِ سند از اصطلاحاتِ پرزرق‌وبرق زیاد استفاده نکن. سعی کن به ذهنِ خواننده‌ت فکر کنی — آیا واقعاً می‌فهمن چی داری می‌گی؟

گاهی می‌خوای مفاهیم مختلفِ طراحی رو تجسم کنی — این رو توی سندی که بعداً توی این دوره بررسیش می‌کنیم می‌بینی. برای این کار، از هر نرم‌افزاری که دستته استفاده کن — می‌تونه PowerPoint باشه، Visio، Keynote، هر چیزی که بهت می‌سازه. فقط مطمئن شو تجسم واضح، مختصر و باکیفیته و پر از شکل و آیتم‌های غیرضروری نیست.

### اگه مشتری صراحتاً بخواد UML

اگه مشتری صراحتاً بخواد دیاگرام‌های UML توی سند باشه (و مدرس این دوره توی کل کارش فقط یه‌بار با همچین مشتری‌ای برخورد کرده)، کافیه چند تا آموزش UML رو مرور کنی و با ابزارهایی مثل Visio دیاگرام‌ها رو بسازی. اگه با PowerPoint راحتی، اون هم می‌تونه به‌راحتی برای همین دیاگرام‌ها استفاده بشه.

### جمع‌بندی

سند معماری باید ساده باشه. از زبان ساده برای توصیفِ نیازمندی‌ها، مفاهیم و طراحی استفاده کن، و برای تجسم‌سازی، از ابزار موردعلاقه‌ی خودت استفاده کن.
