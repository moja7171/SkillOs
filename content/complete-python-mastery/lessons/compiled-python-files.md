## یه پوشه‌ی جدید که خودش ظاهر می‌شه

فرض کن `app.py` رو داری که ماژول `sales.py` رو import می‌کنه. وقتی `app.py` رو اجرا می‌کنی:

```bash
python app.py
```

یه پوشه‌ی جدید به اسم `__pycache__` ظاهر می‌شه. داخلش یه فایل با اسمی شبیه `sales.cpython-37.pyc` هست — نسخه‌ی **کامپایل‌شده**ی ماژول `sales`.

## چرا پایتون این فایل رو می‌سازه

هدف، سریع‌تر شدن **لودشدن** ماژوله (نه سریع‌تر شدن خود اجرای برنامه). دفعه‌ی بعد که `app.py` رو اجرا کنی، پایتون به `__pycache__` نگاه می‌کنه؛ اگه نسخه‌ی کامپایل‌شده‌ی `sales` رو اونجا پیدا کنه، مستقیم همونو لود می‌کنه و مرحله‌ی کامپایل رو رد می‌کنه.

## پایتون کِی این فایل رو دوباره می‌سازه

پایتون تاریخ-زمانِ (timestamp) فایل سورس (`sales.py`) رو با فایل کامپایل‌شده مقایسه می‌کنه. اگه فایل سورس جدیدتر باشه (یعنی بعد از آخرین کامپایل تغییر کرده)، پایتون می‌فهمه کد عوض شده و دوباره کامپایلش می‌کنه.

`cpython-37` توی اسم فایل هم نسخه‌ی پیاده‌سازی پایتونی (CPython) که این فایل رو کامپایل کرده رو نشون می‌ده.

## چرا فقط `sales.py` کامپایل می‌شه، نه `app.py`

نکته‌ی جالب: توی `__pycache__` فقط نسخه‌ی کامپایل‌شده‌ی `sales` رو می‌بینی، نه `app`. چون `app.py` همون فایلیه که مستقیماً از خط فرمان اجراش کردیم (`python app.py`) — پایتون همیشه ماژولی که به‌عنوان نقطه‌ی ورود (entry point) مستقیم اجرا می‌شه رو هر بار از نو کامپایل می‌کنه، ولی ماژول‌هایی که **import** می‌شن (مثل `sales`) رو کش می‌کنه.

## جمع‌بندی

`__pycache__` یه مکانیزم خودکار برای سرعت‌بخشیدن به لودشدن ماژول‌هاست — چیزی نیست که خودت بهش دست بزنی یا نگرانش باشی؛ پایتون خودش مدیریتش می‌کنه.
