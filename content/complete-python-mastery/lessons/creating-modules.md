## یه فایل، خیلی زیاد کد

تا الان همه‌ی کدهامون رو توی یه فایل نوشتیم. ولی یه برنامه‌ی واقعی می‌تونه ده‌ها هزار خط کد داشته باشه — نوشتن همه‌شون توی یه فایل مثل رفتن به یه سوپرمارکتیه که هیچ بخش‌بندی نداره: همه‌چیز قاطی همه‌چیزه و پیداکردن هرچیزی سخته. توی سوپرمارکت، هر بخش محصولات مرتبط رو کنار هم می‌ذاره (میوه‌ها یه‌جا، لوازم شوینده یه‌جا). توی برنامه‌نویسی هم همین اصل رو داریم: کد رو بین چند فایل تقسیم می‌کنیم. به هر فایل می‌گیم **ماژول** (module).

## یه ماژول جدید می‌سازیم

فرض کن توی `app.py` این دو تا تابع رو داریم که هر دو به مفهوم «فروش» مربوطن:

```python
def calculate_tax():
    pass


def calculate_shipping():
    pass
```

چون این دو تا کاملاً به هم مرتبطن، بیایم توی یه فایل جداگونه به اسم `sales.py` بذاریمشون (طبق قرارداد نام‌گذاری، حروف کوچیک و زیرخط بین کلمات):

```python
# sales.py
def calculate_tax():
    pass


def calculate_shipping():
    pass
```

## سه روش برای import کردن

**۱. import کردن اسم‌های مشخص از ماژول:**

```python
from sales import calculate_shipping, calculate_tax

calculate_shipping()
```

دقت کن اسم فایل رو بدون `.py` می‌نویسیم — فقط `sales`، نه `sales.py`.

**۲. import کردن کل ماژول به‌عنوان یه آبجکت:**

```python
import sales

sales.calculate_shipping()
```

اینجا `sales` خودش یه آبجکته و توابعش با نقطه در دسترسن.

**۳. چیزی که نباید بنویسی:**

```python
from sales import *
```

این «همه‌چیز رو import کن» به‌نظر راحت میاد، ولی یه عادت بده: اگه ماژول چند تا اسم داشته باشه که تصادفاً با اسم‌های موجود توی فایل فعلی یکی باشن، بدون هیچ هشداری جایگزینشون می‌کنه. همیشه فقط چیزی که واقعاً لازم داری رو import کن.

## کدوم روش بهتره؟

بین روش اول و دوم، فرقی از نظر کارایی نیست — چون هر بار که یه چیز از یه ماژول import می‌شه، کل اون ماژول لود می‌شه، چه یه تابع ازش بخوای چه همه‌ش. انتخاب بین این دو روش کاملاً سلیقه‌ایه.
