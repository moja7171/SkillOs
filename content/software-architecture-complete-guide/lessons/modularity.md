## ماژولاریته

ماژولاریته یکی از مهم‌ترین ویژگی‌های کیفیه. ماژولار کردن اپلیکیشن واقعاً توی درازمدت کمکت می‌کنه — تلاش لازم برای نگهداری اپلیکیشن رو کاهش می‌ده و انعطافش رو در برابر تغییرات خیلی بیشتر می‌کنه.

پس یه سیستم ماژولار دقیقاً چیه؟ به زبان ساده، یه سیستم ماژولار، سیستمیه که از بلوک‌های سازنده‌ی کوچیک و کاملاً مشخص ساخته شده که می‌شه بدون تأثیر روی کل سیستم، عوضشون کرد یا جایگزینشون کرد.

### یه مثال

فرض کن یه سیستم داریم که داده رو از API یه سیستم دیگه می‌گیره و توی دیتابیس ذخیره می‌کنه.

توی یه سیستم غیرماژولار، هر دو کارکرد — گرفتن داده و ذخیره‌ش توی دیتابیس — توی یه کامپوننت واحد انجام می‌شن. این انتخاب راحت‌تره، ولی بدترین انتخاب هم هست. فرض کن سیستم بیرونی با یه سیستم جدید جایگزین بشه — در نتیجه، API عوض می‌شه و کد اپلیکیشن که بهش دسترسی داره باید بازنویسی بشه. توی یه سیستم غیرماژولار، این تغییر کل اپلیکیشن رو تحت‌تأثیر قرار می‌ده. چون اپلیکیشن فقط از یه کامپوننت تشکیل شده، حالا باید کل اپلیکیشن رو تست و دوباره دیپلوی کنیم — انگار داریم برای اولین بار سیستم رو دیپلوی می‌کنیم. چاره‌ای نداریم؛ کل اپلیکیشن تحت‌تأثیر قرار می‌گیره.

از طرف دیگه، اگه اپلیکیشن ماژولار باشه، کدی که به API دسترسی داره، توی یه کامپوننت کوچیک و مستقل کپسوله شده. اگه API سیستم دیگه تغییر کنه، فقط همون کامپوننت خاص باید تغییر کنه و بقیه‌ی سیستم دست‌نخورده می‌مونه.

همون‌طور که می‌بینی، این باعث می‌شه یه سیستم خیلی منعطف‌تر و قابل‌نگهداری‌تر داشته باشیم — چرخه‌های دیپلوی کوتاه‌تری داشته باشیم و موقع اضافه‌کردن یا آپدیت‌کردن کامپوننت‌ها، وقت زیادی صرفه‌جویی کنیم.
