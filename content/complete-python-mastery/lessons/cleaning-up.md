## منابع خارجی باید آزاد بشن

وقتی با یه منبع خارجی کار می‌کنی — فایل، اتصال شبکه، اتصال دیتابیس — بعد از تموم‌شدن کار باید آزادش کنی. مثلاً یه فایل که باز کردی، باید ببندیش؛ وگرنه ممکنه یه برنامه‌ی دیگه نتونه بازش کنه.

```python
try:
    file = open("app.py")
    print(file)
except FileNotFoundError:
    print("file not found")

file.close()
```

## مشکل: `close()` قابل‌اعتماد نیست

اگه `open("app.py")` استثنا صادر کنه (فایل پیدا نشه)، کنترل می‌ره سراغ `except`، پیام رو چاپ می‌کنه، و بعد به خط `file.close()` می‌رسه — ولی چون `file` هیچ‌وقت واقعاً ساخته نشد (چون همون خط اول شکست خورد)، این‌بار یه `NameError` جدید می‌گیریم: `name 'file' is not defined`. اگه `close()` رو ببری **داخل** `try` هم مشکل حل نمی‌شه — اون‌وقت فقط وقتی اجرا می‌شه که هیچ استثنایی رخ نداده باشه، که دقیقاً همون وضعیتیه که به `close()` کمتر نیاز داری.

## راه‌حل: بلوک `finally`

```python
try:
    file = open("app.py")
    print(file)
except FileNotFoundError:
    print("file not found")
finally:
    file.close()
```

بلوک `finally` **همیشه** اجرا می‌شه — چه استثنایی رخ بده چه نده. دقیقاً همین ویژگیش، بهترین جا برای آزادکردن منابع خارجیه: فایل، اتصال دیتابیس، اتصال شبکه، هرچی که باید «هر جور شده» بسته بشه.

## جمع‌بندی رفتار `try`/`except`/`finally`

| بلوک | کِی اجرا می‌شه |
|---|---|
| `try` | همیشه — اولین چیزی که اجرا می‌شه |
| `except` | فقط اگه توی try استثنای متناظر رخ بده |
| `else` | فقط اگه توی try **هیچ** استثنایی رخ نده |
| `finally` | همیشه — چه استثنا رخ بده چه نده |
