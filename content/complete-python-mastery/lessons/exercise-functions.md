> این درس دو ویدیو داره: خود تمرین، و جواب.

## چالش: FizzBuzz

FizzBuzz یکی از معروف‌ترین سؤال‌های مصاحبه‌ی برنامه‌نویسیه — با اینکه ساده‌ست، خیلی از برنامه‌نویس‌ها (حتی باتجربه‌ها) توی جا انداختنش گیر می‌کنن. یه تابع `fizz_buzz(input)` بنویس که:

- اگه `input` بر ۳ بخش‌پذیر باشه، `"Fizz"` برگردونه.
- اگه بر ۵ بخش‌پذیر باشه، `"Buzz"` برگردونه.
- اگه هم بر ۳ هم بر ۵ بخش‌پذیر باشه، `"FizzBuzz"` برگردونه.
- در غیر این صورت، خود `input` رو برگردونه.

مثلاً `fizz_buzz(3)` باید `"Fizz"` بده، `fizz_buzz(15)` باید `"FizzBuzz"` بده، `fizz_buzz(7)` باید `7` بده. ۱۰ تا ۱۵ دقیقه روش وقت بذار، بعد بیا جواب رو ببین.

## قدم اول: یه نسخه‌ی ساده

```python
def fizz_buzz(input):
    if input % 3 == 0:
        result = "Fizz"
    else:
        result = "Buzz"
    return result
```

این نسخه کار می‌کنه، ولی بهترین شکلش نیست — بریم تمیزترش کنیم.

## قدم دوم: حذف متغیر اضافه

چون توی هر شاخه فقط داریم یه مقدار رو برمی‌گردونیم، نیازی به متغیر واسط `result` نیست — مستقیم `return`:

```python
def fizz_buzz(input):
    if input % 3 == 0:
        return "Fizz"
    else:
        return "Buzz"
```

## قدم سوم: حذف `else` اضافه

وقتی توی بدنه‌ی `if` یه `return` داری، دیگه نیازی به `else` نیست — چون اگه شرط `False` باشه، کنترل خودش می‌ره سراغ خط بعدی:

```python
def fizz_buzz(input):
    if input % 3 == 0:
        return "Fizz"
    return "Buzz"
```

این تکنیک هم تورفتگی رو کم می‌کنه هم کد رو خطی‌تر (linear) می‌کنه.

## قدم چهارم: برگردوندن به قانون‌های واقعی — و یه باگ ظریف

حالا بیایم همه‌ی قانون‌ها رو اضافه کنیم:

```python
def fizz_buzz(input):
    if input % 3 == 0:
        return "Fizz"
    if input % 5 == 0:
        return "Buzz"
    if input % 3 == 0 and input % 5 == 0:
        return "FizzBuzz"
    return input
```

با `fizz_buzz(3)` و `fizz_buzz(5)` درست کار می‌کنه، ولی `fizz_buzz(15)` باید `"FizzBuzz"` بده، در حالی که این نسخه `"Fizz"` می‌ده! چرا؟

چون شرط اول (`input % 3 == 0`) برای ۱۵ هم `True`ه، و همون اول `return` می‌کنه — پایتون هیچ‌وقت به شرط سوم (چک `FizzBuzz`) نمی‌رسه.

## قدم پنجم: شرط دقیق‌تر رو اول بذار

**قانون کلی:** توی یه رشته از شرط‌ها که هر کدوم `return` جدا داره، **شرط دقیق‌تر و خاص‌تر باید زودتر بیاد** — وگرنه یه شرط عمومی‌تر زودتر گیرش می‌ندازه و جلوی رسیدن بهش رو می‌گیره:

```python
def fizz_buzz(input):
    if input % 3 == 0 and input % 5 == 0:
        return "FizzBuzz"
    if input % 3 == 0:
        return "Fizz"
    if input % 5 == 0:
        return "Buzz"
    return input
```

می‌تونیم شرط اول رو هم با پرانتز خواناتر کنیم:

```python
if (input % 3 == 0) and (input % 5 == 0):
    return "FizzBuzz"
```

الان `fizz_buzz(15)` درست `"FizzBuzz"` می‌ده، و بقیه‌ی حالت‌ها هم همون‌طور که انتظار داری کار می‌کنن.

## نکته‌ی مهم

وقتی یه تابع می‌نویسی، فرض نکن درست کار می‌کنه — **با چند تا مقدار مختلف امتحانش کن** (اینجا: یه مضرب ۳، یه مضرب ۵، یه مضرب هر دو، و یه عدد که هیچ‌کدوم نیست). دقیقاً همین تست بود که باگ بالا رو لو داد.
