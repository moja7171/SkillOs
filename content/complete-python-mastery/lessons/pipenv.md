## یه ابزار، به‌جای دوتا

توی دو درس قبل، `pip` رو برای نصب پکیج، و `venv` رو برای ساخت محیط مجازی دیدیم — دو تا ابزار جدا، با دو تا مجموعه دستور جدا که باید حفظشون کنی. **Pipenv** این دو تا رو توی یه ابزار واحد ترکیب می‌کنه (شبیه npm برای جاوااسکریپت): دیگه لازم نیست خودت جدا `venv` بسازی و جدا `pip` رو صدا بزنی.

## نصب Pipenv

```bash
pip install pipenv
```

## نصب یه پکیج با Pipenv

به‌جای `pip install`، از `pipenv install` استفاده می‌کنیم:

```bash
pipenv install requests
```

این یه دستور، سه تا کار رو با هم انجام می‌ده:

1. اگه محیط مجازی برای این پروژه وجود نداشته باشه، خودش می‌سازتش.
2. پکیج `requests` رو داخل همون محیط مجازی نصب می‌کنه.
3. دو تا فایل (`Pipfile` و `Pipfile.lock`) توی پروژه می‌سازه که وابستگی‌ها رو ثبت می‌کنن — توی درس بعدی می‌بینیمشون.

## محیط مجازی، بیرون از پوشه‌ی پروژه

برخلاف `venv` (که پوشه‌ی محیط مجازی رو مستقیم داخل پروژه می‌ساخت)، Pipenv عمداً محیط مجازی رو **بیرون** از پوشه‌ی پروژه نگه می‌داره — چون با نصب چند صد یا چند هزار پکیج، حجم این پوشه خیلی زیاد می‌شه و نمی‌خوایم بخشی از پروژه حساب بشه:

```bash
pipenv --venv
```

این دستور مسیر محیط مجازیِ همین پروژه رو نشون می‌ده.

## فعال‌سازی

```bash
pipenv shell
```

این دستور، محیط مجازی همین پروژه رو فعال می‌کنه — دقیقاً معادل همون `source env/bin/activate` قبلی، فقط بدون نیاز به دونستن مسیر دقیق پوشه. برای خروج:

```bash
exit
```

## جمع‌بندی

`pipenv install <package>` هم پکیج نصب می‌کنه، هم در صورت نیاز محیط مجازی می‌سازه؛ `pipenv shell` محیط مجازی رو فعال می‌کنه. یه ابزار، به‌جای هماهنگ‌کردن دستی `pip` و `venv` با هم.
