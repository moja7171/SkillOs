## مهارت تیم توسعه‌ی فعلی

موقع انتخاب پشته‌ی فناوری — که یکی از مهم‌ترین بخش‌های طراحیِ سیستمه — همیشه دانش و مهارت‌های فعلیِ تیم توسعه رو در نظر بگیر. تصمیم‌گیری درباره‌ی یه پشته‌ی فناوری‌ای که تیم توسعه باهاش آشنا نیست، می‌تونه دو مشکل ایجاد کنه.

### مشکل اول: تأخیر

توسعه‌دهنده‌ها باید وقت بذارن تا با فناوریِ جدید آشنا بشن. این روی زمان‌بندیِ پروژه اثر می‌ذاره و می‌تونه به تحویلِ دیرهنگام منجر بشه.

### مشکل دوم: کیفیتِ پایین

چون این سیستم اولین سیستمی خواهد بود که تیم توسعه با پشته‌ی فناوریِ انتخاب‌شده می‌سازه، توسعه‌دهنده‌ها تجربه‌ای با این پلتفرم ندارن و نمی‌دونن چطور از تله‌های رایج دوری کنن، best practiceها رو پیاده کنن و از قابلیت‌های پنهانی که توی هر پلتفرم توسعه هست بهره ببرن.

### همه‌ی مهاجرت‌ها یکسان نیستن

باید توجه کرد که همه‌ی جابه‌جایی‌های پلتفرم یکسان نیستن. مثلاً برای توسعه‌دهنده‌های بک‌اند، مهاجرت از .NET به Java ممکنه یه‌کم تلاش بخواد، ولی در نهایت، این‌ها پلتفرم‌های نسبتاً مشابهی‌ان — اگه توسعه‌دهنده توی .NET کارش خوب بوده، احتمالاً توی Java هم توسعه‌دهنده‌ی خوبی می‌شه.

از طرف دیگه، یه توسعه‌دهنده‌ی دسکتاپِ ویندوز که می‌خواد به توسعه‌ی بک‌اندِ Python مهاجرت کنه، وضعیت خیلی سخت‌تری داره تا بشه یه توسعه‌دهنده‌ی خوبِ Python. نه‌تنها توسعه‌ی دسکتاپ از نظر مفهومی خیلی با توسعه‌ی وب فرق داره و به یه طرز فکر متفاوت نیاز داره، بلکه خودِ پلتفرم‌ها هم کاملاً متفاوت‌ان. حرکت از یه زبانِ شیءگرا و static-typed مثل .NET به Pythonِ dynamic، ممکنه اصلاً راحت نباشه.

### جمع‌بندی

موقع ارزیابیِ پشته‌های مختلفِ فناوری، همیشه بررسی کن مهارت‌های فعلیِ تیم توسعه چیه و سعی کن بفهمی این انتخاب چه تأثیری روی زمان‌بندی و کیفیتِ پروژه می‌ذاره.
