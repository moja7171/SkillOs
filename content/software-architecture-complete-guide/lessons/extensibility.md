## توسعه‌پذیری

ویژگی کیفیِ بعدی، توسعه‌پذیری (extensibility)ـه. یه سیستمِ توسعه‌پذیر، سیستمیه که می‌شه کارکردش رو گسترش داد، بدون اینکه کد موجودش تغییر کنه.

### یه مثال واقعی

فرض کن یه سیستم اطلاعاتی داریم که یه API برای کوئری‌گرفتن از داده‌هاش داره. این API یه پارامتر به اسم `format` داره که فرمت دقیق داده‌ی برگشتی رو مشخص می‌کنه. روز اول، سیستم دو فرمت رو پشتیبانی می‌کنه: JSON و XML. همه از این فرمت‌ها راضی‌ان و سیستم عالی کار می‌کنه.

بعد یه روز، یه نیازمندی جدید می‌رسه: یه فرمت جدید باید به لیست اضافه بشه — CSV.

توی یه سیستم ساده‌لوحانه، بخشی که فرمت رو می‌سازه، یه کلاس واحد با یه دستور `switch` بوده که بررسی می‌کنه فرمت درخواستی چیه و بر اساسش کد اجرا می‌کنه. توی همچین کدی، نیازمندی جدید یه مشکل جدی ایجاد می‌کنه — حالا باید یه تکه‌ی مرکزی از کد رو تغییر بدیم و همه‌ی تست‌هایی که لازمه رو انجام بدیم تا مطمئن بشیم چیزی رو خراب نکردیم.

### توی یه سیستم توسعه‌پذیر چطوره؟

فرایند کاملاً متفاوته. توی همچین سیستمی، لازم نیست کد اصلی رو تغییر بدیم، بلکه بايد **گسترشش** بدیم. منظور از گسترش‌دادن چیه؟ یعنی می‌تونیم کد جدید به اپلیکیشن اضافه کنیم و کارش رو بکنیم، بدون اینکه کد اصلی تغییر کنه.

چند روش برای این نوع گسترش هست — مثل ارث‌بری (inheritance)، فریم‌ورک پلاگین و بیشتر. یکی از رایج‌ترین الگوها، استفاده از یه فریم‌ورک پلاگین همراه با تزریق وابستگی (dependency injection)ـه، شبیه چیزی که این مثال نشون می‌ده:

```
formatter = getFormatter(formatName)  # formatName: "json", "xml", "csv", ...
result = formatter.format(data)
```

توی این کد، نام فرمت (`json`، `xml`، `csv` یا هر فرمت آینده‌ای) به متد فکتوری `getFormatter` پاس داده می‌شه. این متد فکتوری، یه پیاده‌سازی از اینترفیس `IFormatter` رو برمی‌گردونه. توجه کن که کدی که این متد رو صدا می‌زنه، اصلاً نمی‌دونه دقیقاً کدوم پیاده‌سازی برگشته — بعداً بیشتر درباره‌ش صحبت می‌کنیم، ولی نکته‌ی مهمی که باید درباره‌ی ویژگی کیفیِ توسعه‌پذیری بفهمی اینه که همچین روش‌هایی وجود دارن و به ما اجازه می‌دن کارکرد سیستم رو بدون تغییر کدش گسترش بدیم.
