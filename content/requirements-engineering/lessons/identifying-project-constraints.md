## محدودیت پروژه چیه

محدودیت (constraint) یعنی یه عامل یا شرط محدودکننده که روی توانایی سیستم یا پروژه برای رسیدن به نیازمندی‌ها و اهدافش اثر می‌ذاره. می‌تونه بیرونی باشه (مقررات، بازار) یا درونی (بودجه، نیروی متخصص).

شناسایی زودهنگام محدودیت‌ها خیلی مهمه: کمک می‌کنه تصمیم‌های آگاهانه درباره‌ی مصالحه (trade-off) و طراحی بگیریم. اگه محدودیت‌ها رو دیر بشناسیم، نتیجه‌ش انتظارات غیرواقعی، نیازمندی‌های برآورده‌نشده، تأخیر پروژه، و در نهایت شکست پروژه‌ست.

## دو دسته‌ی بزرگ محدودیت

این درس محدودیت‌های پروژه رو (که با «نیازمندی‌های محدودیتی» که قبلاً دیدیم هم‌پوشانی داره، ولی این‌جا تمرکز روی سطح **پروژه**ست، نه فقط سیستم) به دو دسته تقسیم می‌کنه:

### محدودیت‌های منبع (Resource Constraints)

| نوع | مثال |
|---|---|
| بودجه | بودجه‌ی محدود؛ باید توی طراحی یا کیفیت قطعات مصالحه کنیم |
| نیروی انسانی | تعداد محدود مهندس ماهر؛ ممکنه روی زمان‌بندی یا کیفیت اثر بذاره |
| تجهیزات/ابزار/تسهیلات | عدم دسترسی به تجهیزات تخصصی تست یا کنترل کیفیت |

راه‌حل‌های رایج: همکاری با سازمان‌های دیگه، استفاده از نرم‌افزار متن‌باز یا کدهای پروژه‌ی قبلی، آموزش نیروی موجود یا استخدام تخصص جدید.

### محدودیت‌های کسب‌وکار (Business Constraints)

| نوع | مثال |
|---|---|
| قابلیت فنی | یه فناوری جذاب هنوز به‌اندازه‌ی کافی بالغ/قابل‌اعتماد نیست |
| مقرراتی | استانداردهای ایمنی، محدودیت‌های زیست‌محیطی روی متریال |
| زمان‌بندی | زمان ورود به بازار، ددلاین پروژه |
| بازار | ترجیحات مشتری، رقابت |
| مالی | هدف هزینه، بازگشت سرمایه (ROI) |

## چند نکته‌ی مهم درباره‌ی این محدودیت‌ها

**تیم بازاریابی هم یه ذی‌نفعه.** گاهی مهندسان طراح تصور خودشون از خواسته‌ی مشتری دارن که با تحقیقات واقعی تیم بازاریابی فرق می‌کنه. باید کانال ارتباطی روشنی بین تیم طراحی و بازاریابی برقرار بشه، و تیم بازاریابی از همون ابتدای پروژه درگیر باشه.

**محدودیت‌های قابلیت فنی می‌تونن غافل‌گیرکننده باشن.** ممکنه بخوایم یه فناوری جدید و جذاب رو به کار ببریم، ولی بفهمیم هنوز برای استفاده‌ی عملی به‌اندازه‌ی کافی بالغ نیست — این‌جا باید گزینه‌های جایگزین رو در نظر بگیریم.

## چطور محدودیت‌ها رو شناسایی کنیم

1. **جمع‌آوری اطلاعات** درباره‌ی سیستم، پروژه، ذی‌نفعان و عوامل بیرونی (مقررات، شرایط بازار).
2. استفاده از تکنیک‌های تحلیل و بارش فکری:
   - **مصاحبه** با ذی‌نفعان، تأمین‌کنندگان، کارشناسان.
   - **بارش فکری و نقشه‌ی ذهنی** برای کشف محدودیت‌های نادیده‌گرفته‌شده.
   - **تحلیل SWOT** (نقاط قوت، ضعف، فرصت‌ها، تهدیدها).
   - **تحلیل PESTLE** (سیاسی، اقتصادی، اجتماعی، فناورانه، قانونی، زیست‌محیطی) — برای عوامل بیرون از سازمان.
   - **تحلیل داده‌های تاریخی** پروژه‌های قبلی — چالش‌های تکرارشونده رو شناسایی می‌کنه.
3. محدودیت‌های شناسایی‌شده رو **دسته‌بندی و اولویت‌بندی** کن (بر اساس میزان تأثیر).
4. محدودیت‌ها رو **مستند و مدیریت** کن — تبدیلشون کن به نیازمندی‌های محدودیتی، و مرتب بازبینیشون کن چون ممکنه در طول پروژه تغییر کنن.

## چطور محدودیت‌ها رو مدیریت کنیم

بعد از شناسایی، چهار راه معمول برای مواجهه با یه محدودیت هست:

- **کاهش (Mitigate):** علت ریشه‌ای رو پیدا کن و یه راه‌حل جایگزین برای کم‌کردن اثرش پیدا کن.
- **پذیرش (Accept):** بعضی محدودیت‌ها رو باید پذیرفت و برنامه (زمان‌بندی، بودجه، دامنه) رو باهاشون تنظیم کرد.
- **تعویق (Defer):** پیاده‌سازی یه فیچر/نیازمندی رو به فاز یا پروژه‌ی بعدی موکول کن، وقتی می‌شه بهتر باهاش کنار اومد.
- **مطالعه‌ی تطبیقی (Trade Study):** گزینه‌های طراحی مختلف رو از نظر هزینه، زمان‌بندی و تأثیر فنی مقایسه کن تا بهترین راه رو انتخاب کنی.

چند تمرین خوب: همه‌ی ذی‌نفعان (مشتری، تأمین‌کننده، کارشناس، بازاریابی و فروش) رو توی شناسایی محدودیت‌ها درگیر کن؛ محدودیت‌ها رو **دقیق و قابل‌سنجش** تعریف کن؛ مرتب بازبینی و به‌روزرسانیشون کن؛ و یه فرهنگ مدیریت محدودیت (ارتباط باز بین بخش‌ها) توی سازمان بساز.

> جمع‌بندی: محدودیت رو نمی‌شه نادیده گرفت یا دور زد — ولی می‌شه هوشمندانه مدیریتش کرد. شناسایی زودهنگام، دسته‌بندی، و انتخاب استراتژی درست (کاهش/پذیرش/تعویق/مطالعه‌ی تطبیقی) کلید موفقیته.
