## قراردادهای نام‌گذاری

قراردادهای نام‌گذاری (naming conventions)، یه سری قانون‌ان که تعیین می‌کنن اجزای مختلف کد — مثل کلاس‌ها، متدها، متغیرها، ثابت‌ها و بیشتر — چطور نام‌گذاری می‌شن. نقش این قراردادها اینه که کدمون خواناتر و قابل‌فهم‌تر بشه. وقتی سر یه قرارداد به توافق برسیم، هر تکه‌کد واضح‌تر می‌شه و عناصر مختلفش راحت‌تر از هم قابل‌تشخیصن.

نکته‌ی مهم: قراردادهای نام‌گذاری توسط کامپایلر اجباری نمی‌شن و کد بدون استفاده از هیچ قراردادی هم درست کار می‌کنه. ولی کدی که هیچ قراردادی نداره، شلخته و کار باهاش سخت خواهد بود.

قراردادهای نام‌گذاری معمولاً دو نوع قانون رو پوشش می‌دن: **ساختار نام** (بزرگی/کوچکیِ حروف، خط زیر و…) و **محتوای نام** (چه نوع کلماتی می‌شه توی نام استفاده کرد).

### انواع رایج

**Camel Case:** اگه یه نام بیشتر از یه کلمه داشته باشه، حرف اولِ هر کلمه از دومی به بعد باید بزرگ نوشته بشه. مثلاً کلاسی به اسم `CarEngine`. دو نوع داره: **Upper Camel Case** (که حرف اولِ کلمه‌ی اول هم بزرگه، مثل `CarEngine`) و **Lower Camel Case** (که حرف اولِ کلمه‌ی اول کوچیکه، مثل `carEngine`). Camel case توی Java، #C، JavaScript و Swift خیلی محبوبه و برای نام کلاس توی Python و Ruby هم توصیه می‌شه.

**Lowercase با خط زیر (snake_case):** همون‌طور که از اسمش پیداست، توی این قرارداد فقط حروف کوچیک استفاده می‌شه و کلمات با خط زیر از هم جدا می‌شن — مثلاً یه متغیر به اسم `num_of_parts`. این قرارداد بیشتر توی Python و Ruby برای نام‌گذاریِ متغیرها استفاده می‌شه.

**Capitalized با خط زیر (UPPER_SNAKE_CASE):** شبیه قرارداد قبلیه، با این فرق که فقط از حروف بزرگ استفاده می‌شه — مثلاً `DAYS_IN_WEEK`. این قرارداد اغلب توی Java، Python و Ruby برای نام‌گذاریِ ثابت‌ها استفاده می‌شه.

**نشانه‌گذاریِ مجاری (Hungarian Notation):** توی دهه‌ی نود خیلی محبوب بود و هنوز هم بعضی توسعه‌دهنده‌ها ازش استفاده می‌کنن. این نشانه‌گذاری می‌گه اطلاعات نوعِ متغیر باید بخشی از اسمش باشه. مثلاً اگه یه متغیر از نوع string داری که اسم کوچیک رو نگه می‌داره، اسمش می‌شه چیزی مثل `strFirstName` — یه پیشوندِ کوتاه (معمولاً سه‌حرفی) که نشون‌دهنده‌ی نوعه. این نشانه‌گذاری امروزه چندان رایج نیست و به‌طورکلی بهتره ازش پرهیز بشه.

### محتوای نام

بخش دوم قرارداد نام‌گذاری، به محتوای نام مربوط می‌شه، و یه تمایز مهم اینجا هست: به‌عنوان یه قاعده‌ی کلی، نامِ کلاس‌ها همیشه باید **اسم** باشن و نامِ متدها همیشه باید **فعل امری**. مثلاً یه کلاس که مسئول بازیابیِ داده‌ست باید `DataRetriever` نام‌گذاری بشه (یا حتی ساده‌تر، `Data`)، و متدی توی این کلاس که واقعاً داده رو بازیابی می‌کنه، `RetrieveData` نام می‌گیره. دلیلش اینه که یه کلاس همیشه باید نماینده‌ی یه موجودیت باشه — که با اسم توصیف می‌شه — درحالی‌که یه متد باید نماینده‌ی یه اکشن روی این موجودیت باشه و باید بر همین اساس نام‌گذاری بشه.

### جمع‌بندی

همیشه با یه قرارداد نام‌گذاریِ مشخص کار کن. اینکه دقیقاً کدوم قرارداد رو انتخاب می‌کنی چندان مهم نیست — هرچند خوبه به یه استاندارد رایج پایبند باشی — ولی مهم‌ترین چیز اینه که این تصمیم رو هرچه زودتر بگیری و از همه مهم‌تر، همیشه بهش پایبند بمونی. با این کار، کدت خیلی خواناتر و قابل‌فهم‌تر می‌شه.
