## کلاس‌هایی که فقط داده دارن

بعضی وقت‌ها یه کلاس فقط برای نگه‌داشتن چند تا مقدار می‌سازیم، بدون هیچ رفتار (متد) خاصی:

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y


p1 = Point(1, 2)
p2 = Point(1, 2)

print(p1 == p2)  # False!
```

با اینکه `p1` و `p2` دقیقاً همون مقادیر رو دارن، مقایسه‌شون `False` می‌ده! چرا؟ چون به‌طور پیش‌فرض، پایتون دو تا آبجکت رو بر اساس **محل‌شون توی حافظه** مقایسه می‌کنه، نه مقدارشون. می‌شه با `id()` این رو اثبات کرد:

```python
print(id(p1), id(p2))
# two completely different numbers
```

## راه‌حل قبلی: پیاده‌سازی `__eq__`

توی درس مقایسه‌ی آبجکت‌ها یاد گرفتیم که می‌شه با `__eq__` این رفتار رو عوض کرد:

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
```

```python
print(Point(1, 2) == Point(1, 2))  # True
```

کار می‌کنه، ولی برای یه کلاس که فقط داده نگه می‌داره، نوشتن این‌همه کد کمی زیادیه.

## راه‌حل ساده‌تر: `namedtuple`

برای کلاس‌هایی که فقط داده دارن و هیچ رفتاری ندارن، پایتون یه راه سریع‌تر داره: `namedtuple` از ماژول `collections`:

```python
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
```

آرگومان اول اسم نوعیه که می‌سازیم (به سبک Pascal، چون داره یه نوع/کلاس رو نشون می‌ده)، آرگومان دوم لیست اسم ویژگی‌هاست.

```python
p1 = Point(x=1, y=2)
p2 = Point(x=1, y=2)

print(p1 == p2)  # True -- without writing __eq__ ourselves!
print(p1.x)       # 1
```

## دو تا مزیت

1. **خواناتره**: با آرگومان‌های کلیدی (`x=1, y=2`) دقیقاً معلومه هر مقدار چیه — به‌جای مقادیر بی‌نام که خواننده باید حدس بزنه.
2. **مقایسه‌ی رایگان**: دیگه لازم نیست خودمون `__eq__` بنویسیم؛ `namedtuple` این رفتار رو خودش می‌ده.

## نکته: `namedtuple`ها غیرقابل‌تغییرن

مثل هر تاپل دیگه‌ای، بعد از ساخت نمی‌شه مقادیرش رو عوض کرد:

```python
p1.x = 10
# AttributeError: can't set attribute
```

اگه نیاز به یه مقدار جدید داری، باید یه نمونه‌ی **جدید** بسازی:

```python
p1 = Point(x=10, y=2)
```

پس اگه با کلاسی طرفی که فقط داده داره و رفتاری نداره، `namedtuple` رو در نظر بگیر — کد کمتر، مقایسه‌ی رایگان، فقط باید غیرقابل‌تغییر بودنش رو بپذیری.
