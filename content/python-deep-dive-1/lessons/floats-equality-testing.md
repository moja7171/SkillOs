> این درس دو ویدیو دارد: بخش نظری و بخش کدنویسی.

## مشکل

```python
x = 0.1 + 0.1 + 0.1
y = 0.3
x == y      # False
```

نه باگ پایتون است نه چیزی که با دقت بیشتر حل شود: `0.1` و `0.3` نمایش دودویی متناهی ندارند و تقریبی ذخیره شده‌اند. ولی اگر کدت انتظار `True` داشته باشد، **باگ در کد توست**. (با هشتم‌ها مشکلی نیست: `0.125*3 == 0.375` درست است، چون دقیق‌اند.)

## راه اول: round دو طرف

```python
round(0.1, 1) == 0.3                 # False — round یک float را دقیق‌تر نمی‌کند
round(0.1 + 0.1 + 0.1, 5) == round(0.3, 5)   # True
```

کار می‌کند ولی انعطاف ندارد، و در واقع یک **تلورانس مطلق** پنهان است: «تا ۵ رقم اعشار یکی باشند». معنی خود round هم بعداً غافلگیرت می‌کند (درس گرد کردن).

## راه دوم: تلورانس

دو عدد «برابرند» اگر فاصله‌شان از یک `ε` کوچک کمتر باشد:

```python
def is_equal(x, y, eps):
    return math.fabs(x - y) < eps
```

**تلورانس مطلق** یک عدد ثابت است — و همین مشکل‌ساز است:

```python
x = 0.1 + 0.1 + 0.1;  y = 0.3          # اختلاف ≈ 5×10⁻¹⁷
a = 10000.1 * 3;      b = 30000.3      # اختلاف ≈ 3×10⁻¹²
```

با `ε = 10⁻¹⁵` جفت اول «برابر» و جفت دوم «نابرابر» است — با اینکه نسبت به بزرگی‌شان، دومی حتی نزدیک‌تر است.

**تلورانس نسبی** درصدی از بزرگ‌ترین عدد است: `tol = rel_tol × max(|x|, |y|)`. با `rel_tol = 10⁻⁵`: برای جفت اول tol ≈ 3×10⁻⁶، برای دوم ≈ 0.3 — هر دو «برابر». حل شد؟ نه:

```python
x = 1e-10;  y = 0
# tol = rel_tol × max(|x|, |y|) = 10⁻³ × 10⁻¹⁰ = 10⁻¹³ < اختلاف (10⁻¹⁰) → «نابرابر»
```

نزدیک صفر، تلورانس نسبی خودش به صفر میل می‌کند و هیچ‌وقت راضی نمی‌شود.

## راه درست: ترکیب هر دو (PEP 485)

```
tol = max(rel_tol × max(|x|, |y|),  abs_tol)
```

نزدیک صفر، `abs_tol` حاکم است؛ برای اعداد بزرگ، بخش نسبی. این دقیقاً `math.isclose` است:

```python
from math import isclose
isclose(a, b, rel_tol=1e-09, abs_tol=0.0)     # امضا و پیش‌فرض‌ها
```

**هشدار:** پیش‌فرض `abs_tol` **صفر** است — یعنی بدون تعیینش، فقط تلورانس نسبی داری و نزدیک صفر شکست می‌خوری:

```python
isclose(0.1 + 0.1 + 0.1, 0.3)        # True
isclose(1e-10, 0)                     # False!
isclose(1e-10, 0, abs_tol=1e-5)       # True

isclose(1000.01, 1000.02, rel_tol=1e-5, abs_tol=1e-5)   # True  (نسبتاً نزدیک)
isclose(0.01, 0.02,       rel_tol=1e-5, abs_tol=1e-5)   # False (y دو برابر x است)
isclose(0.0000001, 0.0000002, rel_tol=0.01, abs_tol=0.01)  # True — abs_tol نجاتش داد
```

نکته‌ی مهم آخر: تلورانس‌ها را **یک بار** برای برنامه تعیین می‌کنی، نه برای هر مقایسه — چون نمی‌دانی چه اعدادی می‌آیند. برای همین ترکیب نسبی + مطلق ارزش دارد.

## جمع‌بندی

- float را با `==` مقایسه نکن.
- `math.isclose` با **هر دو** `rel_tol` و `abs_tol`.
- اگر برابری *دقیق* می‌خواهی، اصلاً float نخواه: `Fraction` یا `Decimal` (درس‌های بعد).
