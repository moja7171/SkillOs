## الگوی Command

آخرین الگویی که بررسی می‌کنیم، الگوی Command‌ـه. این الگو نسبت به بقیه‌ی الگوهایی که دیدیم محبوبیت کمتری داره، ولی توی بعضی موقعیت‌ها استفاده‌ش واقعاً کدت رو منعطف‌تر و راحت‌تر برای نگهداری می‌کنه.

اساساً، الگوی Command الگوییه که همه‌ی اطلاعات یه اکشن — شامل نام اکشن، پارامترهاش و آبجکتی که اکشن روش اجرا می‌شه — رو توی یه آبجکت کپسوله می‌کنه. می‌دونم یه‌کم پیچیده به نظر می‌رسه، پس مثل همیشه با یه مثال توضیحش می‌دیم.

### یه مثال: مکانیزم Undo

فرض کن داریم یه مکانیزم Undo (بازگشت به عقب) می‌سازیم. احتمالاً می‌دونی یعنی چی، ولی برای اطمینان: مثل Microsoft Word، جایی که با Ctrl+Z می‌تونی هر اکشنی که انجام دادی رو خنثی کنی و به حالت قبلیِ سند برگردی. این قطعاً یکی از مفیدترین قابلیت‌های هر نرم‌افزاریه و نویسنده‌ها و توسعه‌دهنده‌ها به یه اندازه قدرش رو می‌دونن.

حالا بیا فکر کنیم این مکانیزم چطور پیاده‌سازی می‌شه. مکانیزم Undo باید بتونه تعداد زیادی اکشن رو مدیریت کنه — حذف کاراکتر، تغییر فونت، حذف صفحه از سند، و صدها اکشن دیگه. توی یه پیاده‌سازیِ ساده‌لوحانه، کدِ مکانیزم Undo باید متدی برای همه‌ی این اکشن‌ها داشته باشه. این یه طراحیِ بد‌ه — عملاً کل کارکرد پردازشگر متن رو توی خودش تکرار می‌کنه و حجم کدش تقریباً دو برابر می‌شه. علاوه بر این، هر بار که یه قابلیت جدید به نرم‌افزار اضافه بشه، باید کد جدیدی هم به مکانیزم Undo اضافه بشه — که به یه کدبیسِ عظیم و سخت‌برای‌نگهداری و غیرخوانا منجر می‌شه.

### الگوی Command به کمک میاد

با این الگو، مکانیزم Undo فقط یه لیست از **دستورها (commands)** رو نگه می‌داره که باید اجرا بشن — هیچ ایده‌ای نداره این دستورها چیکار می‌کنن، فقط می‌دونه هر دستور یه متد به اسم `Execute` داره که هر کاری لازمه رو انجام می‌ده.

پیاده‌سازی این‌شکلیه:

**۱. اینترفیس Command:**

```csharp
public interface ICommand
{
    void Execute();
}
```

**۲. کلاس‌های دستورِ خاص** — مثلاً حذف یه کلمه — این اینترفیس رو پیاده‌سازی می‌کنن و هر اطلاعاتی که برای اجرای دستور لازمه رو نگه می‌دارن. مثلاً یه کلاس که یه کلمه رو حذف می‌کنه، احتمالاً به یه ارجاع به سند و به خودِ کلمه‌ای که باید حذف بشه نیاز داره (توی واقعیت، پیاده‌سازی خیلی پیچیده‌تره — مثلاً ارجاع به موقعیت مکان‌نما هم لازمه — ولی برای سادگی همین‌طور نگهش می‌داریم):

```csharp
public class DeleteWordCommand : ICommand
{
    private readonly Document _document;
    private readonly string _word;

    public DeleteWordCommand(Document document, string word)
    {
        _document = document;
        _word = word;
    }

    public void Execute()
    {
        _document.Delete(_word);
    }
}
```

توی الگوی Command، این کلاس **آبجکتِ دستور (command object)** نامیده می‌شه، و سندی که روش کار می‌کنیم **گیرنده (receiver)**.

### حالا برگردیم به مکانیزم Undo

این مکانیزم یه صفِ دستور نگه می‌داره. برای هر اکشنی که روی سند انجام می‌شه، یه آبجکتِ دستور جدید به صف اضافه می‌شه. وقتی Undo درخواست بشه، مکانیزمِ Undo فقط یه دستور رو از صف بیرون می‌کشه و متدِ `Execute`ش رو صدا می‌زنه. توی الگوی Command، مکانیزم Undo، **فراخواننده (invoker)** نامیده می‌شه — فقط متدِ Execute رو صدا می‌زنه.

توجه کن که مکانیزم Undo هیچ‌جا هیچ ایده‌ای نداره واقعاً دستور چیه. تنها چیزی که می‌دونه اینه که یه آبجکتِ دستور با یه متدِ Execute هست که یه اکشن Undoِ خاص رو مدیریت می‌کنه. و همین زیباییِ الگوی Command‌ـه: جداسازیِ کاملِ بین فراخوانیِ دستور و کارکرد واقعیش. فراخواننده هیچ ایده‌ای نداره دستور چیکار می‌کنه — فقط می‌دونه باید فراخوانده بشه. همه‌ی چیزهایی که برای اجرای دستور لازمه، خودش توی آبجکتِ دستور ذخیره شده.

### جمع‌بندی

همون‌طور که گفتیم، الگوی Command نسبت به بقیه‌ی الگوهایی که بررسی کردیم محبوبیت کمتری داره، ولی وقتی به‌کارت بیاد، زندگی و کدت رو خیلی راحت‌تر می‌کنه.
