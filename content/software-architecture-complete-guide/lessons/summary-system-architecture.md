## جمع‌بندی

توی این بخش، درباره‌ی معماری سیستم و جنبه‌های اصلیش حرف زدیم. با استفاده‌ی هوشمندانه از مفاهیمی که یاد گرفتیم — اتصال سست، بدون‌حالت بودن، کش‌کردن، پیام‌رسانی، لاگ‌گیری و پایش — می‌تونی یه معماریِ سیستم طراحی کنی که دووم میاره؛ سیستمت سریع، امن، قابل‌اطمینان و قابل‌نگهداری می‌شه.

یه نکته‌ی مهم: خیلی مهمه که این تصمیم‌ها رو هرچه زودتر و درست بگیری. خیلی از مفاهیمی که توی این بخش بررسی کردیم، بعد از اینکه گرفته شدن، سخت قابل‌تغییرن. مثلاً جابه‌جاشدن از پیام‌رسانیِ مبتنی بر REST API به مبتنی بر صف، باعث می‌شه حداقل بخشی از اجزای سیستم بازنویسی بشه. پس همیشه سعی کن تصمیم‌هات تا حد ممکن آگاهانه باشن.

همچنین یادت باشه این مفاهیم انحصاری نیستن. البته تصمیم‌های بیشتری هم باید در نظر گرفته بشن، و قطعاً کارهای زیادی فراتر از انتخاب لاگ‌گیری و پایشِ درست یا روش پیام‌رسانیِ درست هست. ولی مفاهیمی که توی این بخش بررسی کردیم، معمولاً مهم‌ترین‌ها هستن و توی تقریباً هر سیستمی که طراحی می‌کنی، ازشون استفاده می‌کنی.
